## Продуктовые решения, принятые LLM от твоего имени — проверь

Пока реализация не началась, несогласие правится дёшево (follow-up PR).

- [ ] **Веб-чат по QR — реализация (27.07, spec 0027, PR #111–#114)** — решения UX/операционки, принятые при реализации #79:
  - [ ] **Формат кода заселения**: 6 символов без похожих букв (`K7M-9QT`), печатается CLI один раз при заселении; ресепшен переписывает/показывает гостю с карточки. Терпимый ввод (регистр/дефисы не важны).
  - [ ] **Заселение до кабинета — через CLI на сервере**: `python -m hospitality.tools.checkin 101 --guest "Имя" --nights 2` (перевыпуск `--reissue`, выезд `--check-out-now`, список `--list`). Кнопка «заселить» придёт с кабинетом v1 (#48).
  - [ ] **Контент QR в номере**: `https://staging.necturn.com/g/demo-hotel/<номер-комнаты>` (в проде — прод-домен). Печать QR — твой операционный шаг; сгенерировать можно любым QR-генератором.
  - [ ] **Текст согласия на обработку ПД** на кнопке входа — черновик v0 (одна строка en+ru); финальные kk/ru/en тексты заменит юрпакет. Версия согласия пишется в БД на каждую привязку.
  - [ ] **Телефон ресепшена** в статическом ответе неавторизованным берётся из конфига тенанта (`reception_phone`) — сейчас у demo-hotel НЕ заполнен, надо задать перед пилотом (частично закрывает пункт «Формат статического ответа» ниже; язык ответа — статичный en+ru, per-tenant тексты — не сейчас).
  - [ ] **Один активный Stay на комнату**: второе заселение занятой комнаты CLI отвергает — сначала выезд. Просроченные, но не выписанные проживания CLI помечает «ПРОСРОЧЕН».
- [ ] **ADR-008 (27.07, PR #109)** — [полный текст](adr/ADR-008-identity-and-access.md). Ключевые решения, которые стоит осознанно подтвердить:
  - [ ] **Строгий auth-only до привязки**: неавторизованный гость получает статический ответ без LLM и не может создавать заявки — никаких «пары публичных вопросов» в Phase 1 (это разноска твоего решения 22.07, но теперь оно в камне).
  - [ ] **Код заселения без запасного канала**: SMS/email-доставки нет, только код от ресепшена. Гость без кода = неавторизованный.
  - [ ] **Нет grace-периода после выезда**: checkout мгновенно гасит доступ; забытые вещи и претензии — через ресепшен, не через бота.
  - [ ] **Перевыпуск кода как восстановление**: «гость потерял код» → ресепшен перевыпускает из карточки Stay, старый код гаснет; показать старый код повторно нельзя (в БД только хэш).
  - [ ] **Код многоразовый в пределах проживания**: семья/второе устройство привязываются тем же кодом.
  - [ ] **Продление/ранний выезд правят Stay, не токен**: отдельного действия «продлить доступ гостя» у персонала не будет — только правка дат проживания.
