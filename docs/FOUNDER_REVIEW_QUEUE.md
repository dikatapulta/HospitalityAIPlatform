## Продуктовые решения, принятые LLM от твоего имени — проверь

Пока реализация не началась, несогласие правится дёшево (follow-up PR).

- [ ] **ADR-008 (27.07, PR #109)** — [полный текст](adr/ADR-008-identity-and-access.md). Ключевые решения, которые стоит осознанно подтвердить:
  - [ ] **Строгий auth-only до привязки**: неавторизованный гость получает статический ответ без LLM и не может создавать заявки — никаких «пары публичных вопросов» в Phase 1 (это разноска твоего решения 22.07, но теперь оно в камне).
  - [ ] **Код заселения без запасного канала**: SMS/email-доставки нет, только код от ресепшена. Гость без кода = неавторизованный.
  - [ ] **Нет grace-периода после выезда**: checkout мгновенно гасит доступ; забытые вещи и претензии — через ресепшен, не через бота.
  - [ ] **Перевыпуск кода как восстановление**: «гость потерял код» → ресепшен перевыпускает из карточки Stay, старый код гаснет; показать старый код повторно нельзя (в БД только хэш).
  - [ ] **Код многоразовый в пределах проживания**: семья/второе устройство привязываются тем же кодом.
  - [ ] **Продление/ранний выезд правят Stay, не токен**: отдельного действия «продлить доступ гостя» у персонала не будет — только правка дат проживания.
