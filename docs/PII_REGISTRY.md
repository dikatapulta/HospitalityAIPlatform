# Реестр персональных данных (PII) — FOUNDATION §9

Каждое поле с персональными данными: где живёт, зачем, срок хранения, как
маскируется в логах. **Обновляется в том же PR, что и миграция, добавляющая
PII** (§9); ревью миграции без строки здесь — блокер. Правовая база — юраудит
22.07.2026 (`docs/audits/2026-07-22-legal-recommendations.md`): Закон РК
«О персональных данных» (локализация — ст. 12), GDPR для иностранных гостей.

Сроки хранения решены юрпакетом (issue #126, 28.07.2026) и **исполняются
автоматически** (issue #42, spec 0032): воркер удаляет тексты сообщений и
вопросы гостей без ответа в справочнике (`unanswered_questions`, spec 0036 §6)
старше 90 дней (вместе с опустевшими давно не обновлявшимися диалогами) и
обезличивает свободный текст заявок того же возраста (`channels/common/retention.py`,
настройка `MESSAGES_RETENTION_DAYS`). Удаление по обращению субъекта раньше
срока — вручную (`docs/runbooks/subject-requests.md`). Публичные тексты — в
`docs/legal/` (политика, согласие `consent_version`).

## Не-PII, но секреты (для полноты картины)

`stay_access_codes.code_hash` (bcrypt), `guest_sessions.token_hash` и
`stay_bind_links.token_hash` (SHA-256, миграция 0027 — QR листка гостю),
`user_identities.secret_hash` (argon2id — пароль сотрудника),
`staff_sessions.token_hash` и `staff_invites.token_hash` (SHA-256, миграция
0017), `staff_password_resets.token_hash` (SHA-256, миграция 0032 — ссылка
нового пароля), `staff_known_devices.token_hash` (SHA-256, миграция 0065 —
знакомое устройство входа, spec 0033 §3.3) — секреты доступа, в открытом виде не хранятся и не логируются
никогда (ADR-008); показываются один раз в момент выдачи (пароль не
показывается вовсе — его знает только сотрудник). Исключение —
`staff_second_factors.totp_secret` (миграция 0032): секрет кода из приложения
суперадмина хранится открытым, хэшировать его нельзя — код считает сервер
([spec 0044](specs/0044-superadmin.md) §7); в логи не пишется никогда, второй
экземпляр — в приложении на телефоне основателя.

`staff_passkeys.public_key` (миграция 0070) — открытый ключ WebAuthn: секретом не
является, подделать им подпись нельзя; закрытый ключ не покидает устройство
сотрудника (ADR-008 §8). Одноразовые вызовы церемоний подписи живут в Redis 5 минут
и в БД не попадают.

## Правила

1. Новая PII-колонка → строка в таблице выше в том же PR (§9).
2. PII в логи не пишется; техидентификаторы (chat_id, UUID) — допустимы.
   В том числе на отказе БД: движок не печатает значения параметров SQL в
   тексте исключения (`hide_parameters`, `shared/db.py`, #346). Адрес клиента
   (IP) — тоже PII: в лог — только его сеть, `/24` у IPv4 и `/48` у IPv6
   (`client_network`, `shared/clientip.py`, #173); сам адрес — ключ лимитов
   в Redis, гаснет через два окна лимита (`shared/ratelimit.py`).
3. Удаление данных гостя по запросу (GDPR/ЗПД РК) проектируется при
   добавлении поля: PII должна быть удаляемой без разрушения агрегатов.
