# QUEUE.md — очередь работ

> **Роль:** единственное место, где живёт **порядок** работ. Что именно делать — в issue;
> зачем и по каким критериям — в [PROJECT_EXECUTION_PLAN.md](../PROJECT_EXECUTION_PLAN.md);
> здесь — только «что раньше, что позже» и кто это берёт.
>
> **Статус:** действующий. Заведён 2026-08-04 (правило исполнения 10). Порядок в разделах
> 1–2 выведен из «Exit Gate B» и списка «Осознанно НЕ в Gate B» того же плана — это не
> свежая расстановка приоритетов, а перенос уже принятых решений в один упорядоченный список.

## Как этим пользоваться

**Сессия начинает работу так:** `make queue` → берёт **верхний** пункт раздела 0, если он
не пуст, иначе верхний пункт раздела 1. Пункт «занят», если на него уже есть открытый PR
(это видно в выводе `make queue`).

**Сессия заканчивает работу так:** правит этот файл **в том же PR**, что и саму работу —
вычёркивает сделанное, вписывает новые issue, если ревью или аудит их породили. Находка,
не попавшая ни в один раздел, для следующей сессии не существует.

**Порядок меняет основатель** — перестановка строк здесь и есть решение о приоритете.
LLM-сессия переставляет строки только по явной просьбе; молча — никогда (R-11).

Модель и effort у каждого пункта — по правилу 7 плана; это стартовая оценка, а не приговор:
не решено за два захода — лестница эскалации там же.

## 2. Дорожка «Инфра / Legal» — за основателем

Не конкурирует с дорожкой «Код» за одни руки: это шаги, которые LLM-сессия выполнить не может.
Дедлайн дорожки — **25.08.2026** (пороги уведомительного реестра операторов ПД, закон № 231-VIII).

- **#49** — гейт продакшена: переезд в РК (Kazteleport) по DoD-чеклисту ADR-006 + выделенная non-superuser LOGIN-роль Postgres. **Блокирует первого живого гостя.**
- **#169** (вторая половина) — живая проверка кабинета персонала с телефона: пройти сценарий пальцем на реальном экране. Автотесты этого не видят.
- **ИП** — регистрация; без юрлица не подписать договор с отелем, а обязанности оператора ПД возникают от обработки, не от оплаты.
- **Приказ об ответственном за обработку ПД**; реквизиты ИП в опубликованные юрдокументы; проверка `docs/legal/` юристом.
- **Договор с пилотным отелем** (с DPA-разделом).
- **Сбор фактов для ADR-004** у IT-отдела отеля: доступ к Opera, планировщик отчётов, принтер стойки, Wi-Fi в лобби. Разблокирует пункт 10 дорожки «Код».

## 3. Отложено осознанно — не блокирует пилот

Решение зафиксировано планом («Осознанно НЕ в Gate B») либо самой issue. Строка здесь —
не «забыли», а «посмотрели и решили после пилота». Возврат в раздел 1 — только явным решением.

**Названо планом:** #55 (защита от ошибочного `done`), #82 (фото к заявке), #83 (резолв `#N` при коллизии), #138 (prompt caching — независимо, по ёмкости), #90 (несколько нужд в одном сообщении), #91 (гонка быстрых сообщений) — последние две «если проявятся».

**Названо самой issue:** #117 (dedupe веб-чата — «для пилота приемлемо»), #162 (RBAC v1, пер-тенантный отзыв — «не блокирует пилот, один отель»), #53 (Prometheus multiprocess — Phase 1), #35 (несрочный бэклог после 0017.1).

**Хвосты ревью и мелочи:** #160, #163 (рекомендации ревью PR #155/#159), #173 (IP в `staff.cross_origin_rejected`), #168 (кэш конфига тенанта при поллинге), #157 (разрыв ошибочной привязки гостя), #23 (детали `ValidationError` в лог), #47 (единый язык `AppError`).
