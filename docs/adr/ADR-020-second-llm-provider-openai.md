# ADR-020: Второй LLM-провайдер — OpenAI за портом шлюза, провайдер выводится из модели

- **Статус:** accepted
- **Дата:** 2026-10-05
- **Автор:** LLM-сессия issue #372

> Решение «ставить второго провайдера» принял основатель 28.09.2026 (тело #372),
> довод — цена. Этот ADR его не пересматривает: он фиксирует, **как** второй
> провайдер встаёт за шлюз и при каких условиях он вправе обслуживать живых гостей.

## Контекст

**Цена.** Страницы цен провайдеров на 05.10.2026, $ за 1M токенов (вход/выход):
Sonnet 5 — $2/$10 ([Anthropic](https://platform.claude.com/docs/en/about-claude/pricing));
`gpt-6-luna` — $0,10/$0,50, `gpt-5.6-luna` — $0,20/$1,20
([OpenAI](https://developers.openai.com/api/docs/pricing)). Ход гостя на
Sonnet 5 — ≈3,8 тыс. токенов входа и ≈180 выхода (журнал 10–11.09), то есть
≈$0,009. Те же токены на `gpt-6-luna` стоили бы ≈$0,0005 — в ≈20 раз дешевле;
но токенизатор у OpenAI свой, и на казахском токенов может выйти больше —
настоящую цену хода покажет только замер. Цены выше — справка на дату; их
владелец — прайс-лист шлюза.

**Что уже есть.** Порт `LlmProvider` (`ai/gateway/provider.py`), боевой
адаптер Anthropic, Fake-адаптер `MockLlmProvider` (ADR-007 выполнен — нового
порта нет). Контракты шлюза — простой текст реплик, инструменты как JSON
Schema, `forced_tool` — переводятся в function calling OpenAI без правки.
Импорт-линтер (контракт 4) уже запрещает `openai` вне `ai/gateway`.

**Ограничения.**

- FOUNDATION §14 и ADR-002: «Claude (Anthropic) — основной, за
  провайдер-абстракцией». Второй провайдер как опция этому не противоречит;
  OpenAI основным — противоречит.
- ADR-006: данные гостя у нового субобработчика — юридическая часть, #373.
- ADR-012: Haiku 4.5 на казахском срывался в русский. Модель гостя выбирается
  замером на 6 языках (ADR-010), а не тарифом.
- Fail-fast #137: процесс не поднимается с моделью вне прайс-листа.

**Что выяснилось в день работы (05.10.2026) и повлияло на решения ниже:**

1. У GPT-6 Luna Chat Completions поддерживает function calling **только** при
   `reasoning_effort: "none"`; у GPT-6 Astra и GPT-6.1 Sol инструменты в Chat
   Completions не работают вовсе — OpenAI направляет tool calling в Responses API
   ([Using GPT-6](https://developers.openai.com/api/docs/guides/latest-model)).
2. Кэш промпта у OpenAI включён по умолчанию (implicit), и у GPT-5.6 и новее
   **запись в кэш платная** — 1,25× цены входа
   ([Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching)).
   Порт несёт только `input_tokens`/`output_tokens`: по ним шлюз недосчитал бы
   записи и пересчитал бы чтения — расход и дневной потолок разошлись бы со счётом
   провайдера молча (ровно этот класс ошибки — Д-4 аудита #375).
3. Responses API хранит ответы на стороне OpenAI по умолчанию (`store: true`).
4. Функции в Responses API по умолчанию нормализуются в strict-режим: схема
   переписывается (все поля обязательные), когда это возможно.

## Рассмотренные варианты

**Как выбирается провайдер.**

1. **Отдельная настройка `LLM_PROVIDER`.** Две настройки могут разойтись
   (`LLM_PROVIDER=openai` при `LLM_MODEL=claude-sonnet-5`), и это ещё одна
   проверка на старте. Отвергнут.
2. **По префиксу id** (`gpt-` → OpenAI). Скрытое правило, которого не видно в
   таблице (P-1: никакой магии). Отвергнут.
3. **Прайс-лист — реестр моделей.** Он и так решает, с какой моделью процесс
   вправе стартовать (#137); строки сгруппированы по провайдеру, и та же таблица
   отвечает «кто обслуживает». **Выбран.**

**Какой API OpenAI.**

1. **Chat Completions.** Знаком, но у GPT-6 инструменты в нём ограничены
   (факт 1) — модели следующего поколения потребовали бы переписать адаптер.
2. **Responses API.** Инструменты работают на любой модели и любом уровне
   рассуждений; OpenAI рекомендует его для новых проектов. **Выбран.**

## Решение

1. **Провайдер выводится из модели.** Прайс-лист шлюза
   (`ai/gateway/price_list.py`) сгруппирован по провайдеру; `LLM_MODEL` выбирает
   модель, а с ней и адаптер (`providers.build_provider`) — одна настройка
   переключает обе вещи. Модель в группе `openai` = модель, которую обслуживает
   `OpenAIProvider`.
2. **Адаптер `ai/gateway/openai_provider.py`** по канону `anthropic_provider.py`,
   на Responses API: SDK-ретраи выключены (`max_retries=0`), таймаут →
   `LlmProviderTimeoutError`, прочие сбои SDK → `LlmProviderError`; системная
   инструкция → `instructions`; инструменты → функции с `strict: false` (семантика
   схемы как у Anthropic, без переписывания — факт 4); `forced_tool` →
   `tool_choice={"type": "function", "name": ...}`; аргументы вызова приходят
   JSON-строкой, нечитаемая строка — `LlmProviderError`; токены — из `usage`
   (рассуждения входят в `output_tokens` и оплачиваются как выход), `model` —
   сконфигурированная.
3. **`store: false`** в каждом запросе: шлюз не ведёт диалог на стороне
   провайдера, а лишняя копия реплик гостя у субобработчика — вопрос #373.
4. **Рассуждения выключены (`reasoning.effort: "none"`)** — константа адаптера.
   Ход гостя — короткий ответ или вызов инструмента; Sonnet 5 тоже зовётся без
   extended thinking, и сравнение в bake-off идёт на равных. Не держит качество —
   уровень поднимается правкой константы с новым замером. Модель без `none`
   (GPT-6 Astra, GPT-6.1 Sol) в прайс-лист попадает только вместе с этой правкой.
5. **Кэш промпта у OpenAI выключен** — `prompt_cache_options={"mode": "explicit"}`
   без точек кэша: запросы идут без кэша и без платных записей, стоимость по
   прайс-листу точна (факт 2). Включается вместе с кэшем Anthropic (#138), который
   и так обязан расширить порт токенами кэша — одним контрактом на оба провайдера.
   Цена отказа на нашем ходе — доли цента на тысячу ходов.
6. **SDK `openai>=3.24,<4`.** 3.x ходит через `httpx2`; наш `httpx` и SDK
   Anthropic он не трогает. Верхняя граница — по той же причине, что у
   `anthropic` (#302): мажор SDK уже однажды ронял mypy у каждого PR.
7. **Ключ `OPENAI_API_KEY`**, пустой валиден (dev/CI ходят в Mock). Fail-fast
   старта расширен: модель в прайс-листе **и**, если её провайдер — OpenAI, задан
   ключ. Для Anthropic пустой ключ по-прежнему валиден: это штатный режим
   dev/CI с моделью по умолчанию. Асимметрия намеренная — второй провайдер
   выбирают только намеренно, и выбранный без ключа — заведомо ошибка
   конфигурации, которая иначе вскрылась бы у первого гостя.
8. **Основным остаётся Claude.** Умолчание `LLM_MODEL` — `claude-sonnet-5`;
   FOUNDATION §14 и ADR-002 не меняются. Модель OpenAI обслуживает живых гостей
   (сейчас это гостевая копия пилота) только после трёх условий: юридическая
   часть #373; bake-off на 6 языках с приоритетом казахского — платный прогон с
   согласия основателя; правка FOUNDATION §14 и ADR-002, потому что с этого
   момента «основной» для гостя — OpenAI. До этого модели OpenAI работают только
   на синтетике: bake-off, локальная разработка, staging (ADR-006).

## Последствия

- Проще: цена модели гостя переключается одной настройкой; для третьего
  провайдера рецепт тот же — адаптер, группа в прайс-листе, SDK в контракте 4.
- Сложнее: второй SDK в зависимостях и второй ключ в секретах (`.env` серверов,
  `docs/runbooks/secrets.md`); две страницы цен вместо одной.
- Модель вызова в журнале на исходах timeout/error берётся из настроек, а не из
  провайдера (#268) — при двух провайдерах bake-off пишет такие строки с моделью
  из `LLM_MODEL`. Учёт успешных вызовов это не затрагивает.
- `Smoke` вызывает модель гостя; ADR её не меняет. PR, переключающий
  `LLM_MODEL` на OpenAI, пересчитывает цену прогона в spec 0019 (CLAUDE.md).
- **Пересмотреть**, если: bake-off покажет срыв на казахском — тогда OpenAI
  остаётся опцией без гостей; OpenAI выведет модели из прайс-листа или изменит
  правила кэша и рассуждений; появится маршрутизация моделей (Фаза 1) —
  выбор провайдера по модели переходит в неё.
