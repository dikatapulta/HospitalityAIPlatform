# ADR-024: шлюз — назначение вызова со своей моделью и бюджетом, эмбеддинги и поток

- **Статус:** proposed (PR #499, issue #492)
- **Дата:** 2026-10-28
- **Автор:** LLM-сессия по #492 (Opus 5.5)

> Своя модель (`gpt-6-luna`) и свой дневной бюджет для «Наставника» — решение основателя 27.10.2026
> (тело #492). Этот ADR его не пересматривает: он фиксирует, как шлюз различает назначения, и
> добавляет две нужные наставнику операции.

## Контекст

FOUNDATION §7.2 обещает шлюзу маршрутизацию моделей, бюджеты и приоритеты. Сегодня у него одна
модель `LLM_MODEL`, один дневной бюджет тенанта `LLM_TENANT_DAILY_BUDGET_USD` (потолок $10 —
решение 10.09) и одна операция — `complete()` текстом целиком. Наставнику
([spec 0048](../specs/0048-mentor.md) §5) нужны:

- **эмбеддинги** — поиск статьи кодекса по смыслу;
- **поток** — первое слово раньше; на hr.necturn.com ответ печатается по мере написания с 23.10;
- **своя модель и свой бюджет** — чтобы обучение персонала не тратило бюджет гостевого бота.

Ограничения:

- ADR-017 — резерв бюджета до вызова, ретрай только по таймауту;
- ADR-020 — провайдер выводится из модели по прайс-листу, а модели OpenAI до своих условий
  работают только на синтетике;
- #426 — оплаченный, но не прочитанный ответ попадает в журнал со стоимостью 0;
- P-12 — один путь к модели.

## Рассмотренные варианты

**Модель и бюджет.**

1. **Одна модель и общий бюджет.** Наставник ходил бы на Sonnet 5, а он в 20 раз дороже по
   выходу ($10 против $0,50 за 1M токенов). Сотни вопросов персонала съедали бы $10 гостя.
   Основатель отклонил этот вариант 27.10.
2. **Наставник зовёт OpenAI сам, мимо шлюза.** Нарушает §7.2 и R-5: расхода не видно, потолка
   нет — ровно то, от чего уходим с hr.necturn.com.
3. **Назначение вызова в запросе шлюза; у каждого назначения своя модель и свой бюджет.**
   **Выбран.**

**Эмбеддинги.** Метод `embed` в порту `LlmProvider` пришлось бы писать и у Anthropic, а у него нет
API эмбеддингов. Поэтому эмбеддинги — отдельный протокол `EmbeddingProvider`: реализации OpenAI и
Mock.

**Поиск без эмбеддингов.** Запасной вариант — полнотекстовый поиск Postgres: шлюз не трогается,
но поиск знает только русскую морфологию, а синонимы («заселение» / «check-in», «жалоба» /
«недоволен») не находит. «Наставник» уже ищет эмбеддингами, а пересчёт кодекса стоит доли цента.
Отвергнут для v1.

**Поток.** Метод потока в `LlmProvider` обязал бы адаптер Anthropic реализовать то, чего никто не
вызывает (NG-8). Поэтому поток — отдельный протокол `LlmStreamingProvider`: реализации OpenAI и
Mock. Адаптер Anthropic получит поток, когда назначению понадобится модель Claude.

## Решение

1. **Назначение вызова.** `LlmPurpose = Literal["guest", "mentor"]`. Поле `LlmRequest.purpose` по
   умолчанию `"guest"`: все нынешние вызывающие (оркестратор, перевод, текст о частичном
   выполнении, smoke, bake-off) не меняются. В `ai/gateway/purposes.py` — таблица «назначение →
   настройка модели и настройка бюджета»:

   | Назначение | Модель | Дневной бюджет тенанта |
   |---|---|---|
   | `guest` | `LLM_MODEL` | `LLM_TENANT_DAILY_BUDGET_USD` |
   | `mentor` | `LLM_MODEL_MENTOR` | `LLM_MENTOR_DAILY_BUDGET_USD`, умолчание $2 |

   - У `llm_call_log` и `llm_budget_reservation` появляется колонка `purpose VARCHAR(16) NOT NULL
     DEFAULT 'guest'` (без CHECK, как `status`). `server_default` не снимается: иначе ломается
     откат.
   - Расход за сутки и живые резервы считаются в пределах своего назначения: исчерпанный бюджет
     наставника не трогает гостя, и наоборот.
   - `purpose` не входит в `prompt_hash`: хэш — версия того, что видела модель, а модель и так
     пишется отдельной колонкой.
2. **Назначение может быть выключено на деплойменте.** `LLM_MODEL_MENTOR` по умолчанию пуст: dev и
   CI поднимаются без ключа OpenAI, как сегодня. Вызов с пустой моделью назначения возвращает
   ERR-AI-006 (503): провайдер не вызывается, строка журнала не пишется, только WARNING
   `llm_purpose_not_configured`. Если модель задана, fail-fast старта (`validate_configured_model`,
   #137) проверяет три вещи: модель есть в прайс-листе чатов, её адаптер умеет поток, ключ её
   провайдера задан. При заданной модели наставника то же проверяется и для `LLM_EMBEDDING_MODEL`.
3. **Цены.** Модели эмбеддингов идут отдельной группой прайс-листа (`$` за 1M токенов входа),
   чтобы `LLM_MODEL` не принял модель эмбеддингов за модель чата. Строки сверены со страницей цен
   OpenAI 28.10.2026: `text-embedding-3-small` — $0,02; `gpt-6-luna` — $0,10 / $0,50 (строка уже
   есть, ADR-020). `LLM_EMBEDDING_MODEL` по умолчанию — `text-embedding-3-small`. Размерность 1536
   входит в схему (`vector(1536)`, spec 0048 §4): смена модели эмбеддингов — это миграция плюс
   пересчёт статей.
4. **`embed(texts, *, purpose) -> EmbeddingResponse`** (векторы, модель, токены, стоимость,
   `call_id`). Порядок тот же, что у `complete()`:
   - резерв по оценке входа «символов / 2» (ADR-017), бюджет назначения;
   - попытки с ретраем только по таймауту, стоимость, строка журнала (`output_tokens = 0`,
     `prompt_hash` — sha256 сериализованных текстов), снятие резерва.
   Деление на пачки по лимитам провайдера — внутри адаптера: один вызов шлюза — одна строка.
5. **`stream(request) -> AsyncIterator[LlmStreamEvent]`.** События: `LlmTextDelta(text)`… затем
   `LlmStreamCompleted(response: LlmResponse)`.
   - Резерв и бюджет — до первого байта. Ретрай по таймауту — только пока не пришёл первый кусок.
     После него ошибка даёт ERR-AI-003 и строку `error`, потому что кусок уже ушёл человеку.
   - Инструменты и `forced_tool` в потоке запрещены (`ValueError`): наставнику они не нужны, а
     разбор вызова инструмента по кускам — отдельная работа.
   - **Обрыв.** Потребитель закрыл поток, клиент ушёл или задачу отменили — шлюз пишет строку
     `aborted` со стоимостью резерва. Резерв — верхняя граница: выход ограничен `max_tokens`, вход
     оценён с запасом, так что расход не занижается. Запись идёт под защитой от отмены: отмена в
     Starlette и anyio повторяется на каждом `await`, и без защиты строка не записалась бы.
   - **Нет `usage`.** Поток закончился, но провайдер не прислал число токенов — это тоже
     стоимость резерва, а не 0. Новые пути не наследуют дефект #426 §1.
   - **Остаток #426 §1** (ревью PR #499, Н-1). `complete()` с назначением `mentor` (резюме
     диалога) его наследует: оплаченный, но не прочитанный ответ OpenAI пишется стоимостью 0.
     Инструментов у наставника нет, остаются `response.error` и ответ без `usage`. То же у
     `embed()`, если упала не первая пачка. Чинит #426 — для обоих назначений сразу.
6. **Адаптер OpenAI.** Поток и эмбеддинги работают на том же клиенте. Остаётся всё из ADR-020:
   `store: false`, `reasoning.effort: "none"`, кэш выключен. Ко всем запросам адаптера добавляется
   `service_tier: "default"` (#426 §3): иначе тариф берётся из настроек проекта OpenAI, Fast
   стоит 2×, Flex — 0,5×, и стоимость молча разошлась бы со счётом. Рассуждения выключены и для
   наставника. Ответ по найденным статьям — короткий пересказ, а первое слово на hr.necturn.com
   сегодня ждёт 2–6 с именно из-за рассуждений.
7. **Метрики и алерты гостя видят только `guest`.** `llm_daily_spend_usd`, `llm_daily_budget_usd`,
   серии отказов (#374) и алерты ERR-OPS-006/009/010 фильтруются по назначению `guest`: сбой
   OpenAI у наставника не должен будить основателя словами «гостевой бот молчит». Своих алертов у
   наставника в v1 нет — сотрудник видит текст (spec 0048 §7). Строка сводки дня «ИИ за сутки»
   (spec 0035 §6) делится на гостя и наставника.
8. **OpenAI на живых данных персонала.** ADR-020 §8 держит модели OpenAI на синтетике до своих
   условий, и все они — про гостя: bake-off исхода диалога на 6 языках, #426, решение перевести
   гостей, #373. Для назначения `mentor` условия свои, и проверяются они в PR 5 спеки 0048:
   - разделы DPA о персонале и OpenAI и уведомление сотрудника (spec 0048 §9);
   - живая проверка до 5 вопросов с согласия основателя на план с ценой.
   Сотрудники hr.necturn.com уже работают с той же моделью. Гостевой путь не меняется: §8 ADR-020
   в силе.
9. **FOUNDATION §14 не меняется.** Основная модель платформы — Claude: на ней гостевой диалог.
   Модель назначения — настройка деплоймента, как `LLM_MODEL`.

## Последствия

- Наихудший дневной расход тенанта — $10 гостя плюс $2 наставника. Новое назначение — это строка
  в `purposes.py`, две настройки, проброс в compose (app и worker) и строка в README шлюза.
- Ключ `OPENAI_API_KEY` уже есть (ADR-020), нового секрета нет. `LLM_MODEL_MENTOR`,
  `LLM_EMBEDDING_MODEL` и `LLM_MENTOR_DAILY_BUDGET_USD` — в `.env.example` и compose.
- Новый код ERR-AI-006 — статья в `docs/runbooks/errors.md` в PR 2.
- Пересмотреть, если:
  - появится маршрутизация по сложности (§7.2) — тогда таблица назначений станет её основой;
  - наставнику понадобятся инструменты — нужен поток с инструментами;
  - качество ответов без рассуждений не устроит — нужен уровень рассуждений на назначение, с
    замером, за который платит основатель;
  - назначению понадобится модель Claude — нужен поток в адаптере Anthropic.
