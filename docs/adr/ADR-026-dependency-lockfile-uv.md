# ADR-026: Лок-файл зависимостей — `uv.lock`, установка строго по нему

- **Статус:** accepted
- **Дата:** 2026-11-11
- **Автор:** окно пула 2 (Opus 5.5), по рекомендации issue #305 — слово основателя 10.11 (#909)

## Контекст

Зависимости в `pyproject.toml` записаны диапазонами (`fastapi>=0.115`), лок-файла не было. CI, образ
и `make venv` собирали окружение с нуля и брали то, что лежало на PyPI в момент сборки. Релиз, которого
никто не заказывал, приезжал сам: 25.07.2026 `ruff 0.16.0` покрасил README всего репозитория,
21.08.2026 `anthropic 1.0.0` уронил mypy у каждого PR и остановил мержи (#302). На staging и копии
отеля стояло не то, что проверил CI, а то, что было на PyPI в день деплоя. Dependabot со
стратегией по умолчанию по `>=`-требованиям без лока молчал — менять в файле нечего
(`.github/dependabot.yml`).

С 01.12 в системе живые сотрудники отеля; сломанная сборка в день включения — отказ системы.

## Рассмотренные варианты

1. **Лок-файл `uv.lock`** — точные версии и хэши всех зависимостей, транзитивных тоже, для всех
   платформ и Python ≥ 3.12 одним файлом. Dependabot понимает его родной экосистемой `uv` — версии
   и security-обновления (GitHub, 16.12.2025). Цена — инструмент `uv` в конвейере.
2. **Лок `requirements.txt` из `pip-compile`** — тот же смысл, без нового формата. Отвергнут:
   Dependabot перезапускает `pip-compile` по заголовку файла и не поддерживает `--extra`
   (dependabot-core#6406), а без `--extra dev` половина лока не обновляется; лок под одну платформу
   (Mac основателя и Linux CI разошлись бы маркерами).
3. **Верхние границы на мажор у всех** — без нового инструмента, но минорные и патч-релизы
   по-прежнему приезжают сами (`ruff 0.16.0` был минором), воспроизводимости нет.
4. **`versioning-strategy: increase` без лока** — Dependabot сам поднимает нижние границы `>=`
   (обход dependabot-core#9105 работает с 10.04.2026, dependabot-core#14666; вариант дописан после
   принятия решения — #321). Отвергнут: между PR робота сборка по-прежнему берёт с PyPI любую
   версию выше границы, транзитивные тоже — `ruff 0.16.0` приехал бы так же; цена сверху —
   еженедельный PR, сдвигающий границы всех рантайм-зависимостей.
5. **Ничего не делать** — каждый случай стоит окна сессии и приходит в произвольный день,
   в том числе в день включения у отеля.

## Решение

Вариант 1. `uv.lock` в корне — единственный источник версий. Ставит зависимости один скрипт
`ops/install-deps.sh` (`runtime` — образ, миграции и алерт в CI; `dev` — `make venv`, `check`, smoke):
`uv export --locked` превращает лок в список версий с хэшами, `pip install --require-hashes`
ставит ровно его, пакет проекта — без зависимостей, затем `pip check`. Устанавливает по-прежнему pip:
окружение, `.venv/bin/…` и шаги CI остались прежними, uv только читает и пишет лок. `--locked`
роняет установку, если `pyproject.toml` поправили, а лок не пересобрали; локально то же ловит
`make check` (`tests/test_dependency_lock.py`, он же не даёт CI, образу и Makefile ставить
`pip install` в обход скрипта). Dependabot переведён с экосистемы `pip` на `uv`.

## Последствия

- В CI, образе и на staging — одни и те же версии; апгрейд виден в diff `uv.lock` и проходит CI
  до того, как попасть в образ.
- Правило: правишь зависимости в `pyproject.toml` — `make lock` и коммит `uv.lock` тем же PR.
  Поднять один пакет — `make lock ARGS="--upgrade-package <имя>"`. Старое `.venv` без uv —
  `make venv` заново.
- Исправление CVE больше не приезжает само со следующей сборкой: его приносит PR Dependabot
  на `uv.lock` (security-обновления) или окно руками; merge — как любой PR. `pip-audit` (job `audit`)
  теперь аудирует ровно залоченные версии.
- Версия самого uv — константа в `ops/install-deps.sh`, поднимается осознанным PR. Бэкенд сборки
  `hatchling` ставится при сборке пакета вне лока — ему верхняя граница мажора в
  `[build-system]`.
- Верхние границы (`anthropic<1`, `openai<4`, `pypdf<8` …) остаются: мажор — отдельным PR
  с правкой границы, а не очередным обновлением лока.
- Пересмотреть, если Dependabot перестанет поддерживать `uv` или лок начнёт систематически
  расходиться между платформами.
