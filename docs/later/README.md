## Как вписывать

**Одна находка — один файл** (решение основателя 29.10.2026, #532). Два PR никогда не создают
один и тот же файл, поэтому находки из параллельных окон сливаются без конфликтов — в отличие от
строк, дописанных в конец общего файла.

- **Имя:** `ГГГГ-ММ-ДД-pr<N>-<слово>.md` — дата, номер PR, в котором находка сделана (у окна
  задачи — его заявочный draft-PR), и короткое слово латиницей через дефис: номер находки ревью
  (`n3`) или суть (`api-router-size`). Разные находки одного PR — разные слова. Пример:
  `2026-10-29-pr533-union-merge.md`. Имя не по формату `make later` всё равно печатает,
  но с предупреждением.
- **Внутри** — одна строка прежнего формата; ссылки — от этой папки (`../specs/…`):

  `- [ ] ДД.ММ — <откуда: ревью PR #N / окно задачи #N> — <что и где, одним-двумя предложениями>`

Вписывает тот же PR, где находка сделана: при вердикте changes requested — автор вместе с
доработкой, без блокеров (или когда единственный блокер — номер миграции) — ревьюер коммитом
в ветку PR до approve (правило 9). Сделанную находку удаляет PR, который её сделал: файл
целиком, а строку архива — строкой.
