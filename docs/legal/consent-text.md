# Тексты согласия на обработку персональных данных (kk/ru/en)

> Пакет П1.3 (issue #126). Экран согласия — компактный (v2, решение основателя
> 29.07.2026): одна строка + ссылка на политику + кнопка «Продолжить».
> Обязательные элементы — явное упоминание трансграничной передачи в страну,
> не обеспечивающую защиту (ст. 16), и право возражения против
> автоматизированной обработки (ст. 19-1) — раскрыты в Политике
> конфиденциальности, на которую ведёт ссылка (`privacy-policy.md`, там они
> есть на всех трёх языках). **Юристу подтвердить:** достаточно ли для ст. 8/16
> согласия кнопкой под строкой со ссылкой, когда сама передача названа только
> в политике; если нет — вернуть короткое упоминание передачи в текст экрана
> (см. историю версий ниже). Языки — kk/ru/en (Закон «О языках», ЗоЗПП:
> kk+ru минимум).

## Версия

**`consent_version = "2026-07-29-v2"`**

История:

- **v2 (2026-07-29)** — экран сокращён по требованию основателя: вместо
  четырёх абзацев юртекста — одна строка «Продолжая, вы соглашаетесь…» со
  ссылкой на политику; кнопка «Согласен(на)» → «Продолжить». Кнопка
  сохранена сознательно: без явного действия согласие на трансграничную
  передачу (ст. 16) недоказуемо, а первое сообщение гостя ушло бы в
  обработку до согласия.
- **v1 (2026-07-28)** — полный текст с элементами ст. 16/19-1 прямо на
  экране (история — в git).

Правила (юраудит П1.3):

- Текст ниже — единственный источник истины; код каналов копирует его
  дословно (`channels/common/consent.py`), расхождение ловит
  `tests/test_legal.py`; версия хранится рядом с фактом согласия
  (`conversations.consent_version`, `guest_sessions.consent_version`).
- **Изменил текст по смыслу → подними версию** (дата-vN) в этом файле и в
  коде тем же PR; гости с прежней версией проходят consent-gate заново.
- Плейсхолдеры `[ссылка на политику]` / `[саясат сілтемесі]` /
  `[privacy policy URL]` подставляются в рантайме: политику публикует сама
  платформа — `{PUBLIC_BASE_URL}/legal/privacy` (spec 0029 §2). Условие
  «consent-gate не включается без доступной политики» выполнено
  конструктивно: страница есть всегда, отдельного шага публикации нет.

Показ текста — на языке интерфейса гостя; если язык неизвестен (первый
контакт), показываются **все три версии** (kk+ru — законодательный минимум
информации для потребителя, Закон «О языках»/ЗоЗПП; en — демография пилота).
В Telegram язык берётся из клиента гостя (`from.language_code`), иначе — все
три; в веб-чате до входа язык неизвестен всегда, поэтому там показываются все
три. Версии равнозначны; эталон при правках — русская.

## Примечания для реализации (#127, веб-чат) — реализовано, spec 0029 (+v2)

- Без нажатия кнопки LLM не вызывается вовсе (PEP §Gate B п. 4, вариант A —
  механика сохранена в v2, сменилась только надпись) — это одновременно
  юридический gate и защита бюджета от ботов-сканеров. В Telegram до
  согласия не сохраняется и само содержимое сообщений.
- Факт согласия: `consent_at` (UTC) + `consent_version`; хранится как
  доказательная запись и не удаляется по ретеншну сообщений
  (`docs/PII_REGISTRY.md`). Telegram — `conversations`, веб — `guest_sessions`.
- Текст кнопки и текст экрана — из этого файла дословно; канал показывает
  текст целиком. Элементы ст. 16/19-1 живут в политике по ссылке (см.
  преамбулу — вопрос юристу).
