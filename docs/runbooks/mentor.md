# Рунбук: «Наставник» — включить раздел, загрузить кодекс, следить за тратами

Как включить раздел «Наставник» в кабинете персонала, загрузить или обновить кодекс отеля
и держать траты под потолком. Устройство и числа — [spec 0048](../specs/0048-mentor.md);
модель и бюджет назначения — [ADR-024](../adr/ADR-024-gateway-purpose-embeddings-stream.md);
ключ OpenAI — [secrets.md](secrets.md); коды `ERR-MENTOR-*`, `ERR-AI-002`, `ERR-AI-006` —
[errors.md](errors.md).

Раздел работает, когда верны три вещи разом:

| Что | Где | Если нет |
|---|---|---|
| Модель наставника: `LLM_MODEL_MENTOR` и `OPENAI_API_KEY` | `.env` сервера | «Наставник сейчас не отвечает» (ERR-AI-006) |
| Флаг отеля `mentor_enabled: true` | конфиг тенанта в базе | пункта меню нет, адреса раздела — 404 |
| Кодекс отеля | загрузка в кабинете | «Кодекс ещё не загружен — попросите менеджера» (ERR-MENTOR-002) |

Порядок — именно такой: загрузка кодекса уже зовёт модель (векторы статей), а страница
загрузки видна только при включённом флаге.

## Включить на staging

Делает основатель: запись в `.env` по SSH автоматике запрещена. Команды — на сервере
(`ssh deploy@<IP staging>`), из `/opt/hospitality`.

1. `nano .env` — три строки (пустые заменить, нет — дописать):
   ```
   OPENAI_API_KEY=<ключ из менеджера паролей>
   LLM_MODEL_MENTOR=gpt-6-luna
   LLM_MENTOR_DAILY_BUDGET_USD=2.0
   ```
   и перезапустить процессы:
   ```sh
   docker compose -f docker-compose.staging.yml up -d app worker
   ```
   Модель вне прайс-листа шлюза или без ключа — контейнеры не поднимутся, в логе
   `LLM_MODEL_MENTOR=…` с причиной. Исправить строку и повторить.
2. Флаг отеля. Открыть psql — шаг 1 рецепта «Откат на образ старше #298»
   ([deploy.md](deploy.md)), только вход, без его SQL. Выполнить:
   ```sql
   UPDATE tenants SET config = jsonb_set(config, '{mentor_enabled}', 'true')
   WHERE slug = 'demo-hotel';
   ```
   Ответ `UPDATE 1`. Перезапуск не нужен: кабинет читает флаг на каждом запросе. Деплой
   и сид флаг не сбрасывают.
3. Кодекс. У демо-отеля уже есть вымышленный кодекс из сида — для проверки хватит его.
   Настоящий — раздел «Загрузить или обновить кодекс» ниже.
4. Проверка: войти в кабинет staging → «Наставник» → «Спросить» → вопрос по кодексу.
   Ответ приходит по словам, под ним «Источник: Статья N». Первый вопрос после сида
   дольше обычного: досчитываются векторы статей. Цена вопроса — spec 0048 §8.

## Включить на гостевой копии отеля

Только в PR 5 серии #492 (переключение): кодекс утверждён основателем, юрдокументы
spec 0048 §9 готовы, у всех сотрудников есть логины кабинета — условия spec 0048 §10, п. 5.
Шаги те же, но из каталога копии (`/home/deploy/hospitality-pilot`, [pilot-copy.md](pilot-copy.md))
и со своим `slug` отеля в SQL. Кодекс загрузить сразу после флага: пока его нет, сотрудники
видят «Кодекс ещё не загружен».

## Загрузить или обновить кодекс

Менеджер отеля (или основатель под учёткой менеджера): «Наставник» → «Кодекс» →
«Загрузить кодекс» → выбрать **все** файлы кодекса (`.md`) сразу.

- Новый кодекс заменяет прежний целиком. Ошибка разметки — сообщение с файлом и строкой
  («Файл 20_front_office.md, строка 41: статья 15 вместо 14»), прежний кодекс остаётся.
- Загрузка пересчитывает векторы всех статей (цена — spec 0048 §8) из того же дневного
  бюджета наставника.
- Диалоги сотрудников и оценки «Тренировки» остаются.
- Файлы кодекса в репозиторий не кладутся: он публичный.

## Траты

- **Потолок** — `LLM_MENTOR_DAILY_BUDGET_USD` в `.env`, на отель в сутки, отдельно от
  гостевого бота. Сутки — UTC: новые начинаются в 05:00 по Алматы.
- **Потолок достигнут** — сотрудники до 05:00 видят «Наставник на сегодня ответил на все
  вопросы, что мог…» (ERR-AI-002). Гостевой бот не затронут. Алерты ERR-OPS-006/009/010
  говорят только о госте — исчерпание бюджета наставника их не будит.
- **Где видно расход** — копия утренней сводки основателю: «ИИ за сутки отеля: $… (гостевой
  бот $…, наставник $…)».
- **Изменить потолок** — строка в `.env` и перезапуск, как в шаге 1.

## Выключить

Тот же SQL шага 2 с `'false'`: пункт меню исчезает сразу, кодекс и диалоги остаются (их
стирает ретеншн, spec 0048 §4). Пустой `LLM_MODEL_MENTOR` тоже останавливает траты, но
сотрудники видят «Наставник сейчас не отвечает» — флаг понятнее.
