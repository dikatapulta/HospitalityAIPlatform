# Рунбук: «Наставник» — включить раздел, загрузить кодекс, следить за тратами

Как включить раздел «Наставник» в кабинете персонала, загрузить или обновить кодекс отеля
и держать траты под потолком. Устройство и числа — [spec 0048](../specs/0048-mentor.md);
модель и бюджет назначения — [ADR-024](../adr/ADR-024-gateway-purpose-embeddings-stream.md);
ключ OpenAI — [secrets.md](secrets.md); коды `ERR-MENTOR-*`, `ERR-AI-002`, `ERR-AI-006` —
[errors.md](errors.md).

Раздел работает, когда верны четыре вещи разом:

| Что | Где | Если нет |
|---|---|---|
| Модель наставника: `LLM_MODEL_MENTOR` и `OPENAI_API_KEY` | `.env` сервера | «Наставник сейчас не отвечает» (ERR-AI-006) |
| Флаг отеля `mentor_enabled: true` | конфиг тенанта в базе | пункта меню нет, адреса раздела — 404 |
| Кодекс отеля | загрузка в кабинете | «Кодекс ещё не загружен — попросите менеджера» (ERR-MENTOR-002) |
| Отметка согласия сотрудника «Наставник — OpenAI» ([spec 0082](../specs/0082-staff-ai-consent.md)) | «Сотрудники», галочка в строке | у этого сотрудника пункта меню нет, страница — «Раздел закрыт»; суперадмину отметка не нужна |

Порядок — именно такой: загрузка кодекса уже зовёт модель (векторы статей), а страница
загрузки видна только при включённом флаге.

## Включить на staging

Делает основатель: запись в `.env` по SSH автоматике запрещена. Команды — на сервере
(`ssh deploy@<IP staging>`), из `/opt/hospitality`.

1. `nano .env` — три строки (пустые заменить, нет — дописать):
   ```
   OPENAI_API_KEY=<ключ из менеджера паролей>
   LLM_MODEL_MENTOR=gpt-6-luna
   LLM_MENTOR_DAILY_BUDGET_USD=2.0
   ```
   и перезапустить процессы:
   ```sh
   docker compose -f docker-compose.staging.yml --env-file .env up -d app worker
   ```
   Модель вне прайс-листа шлюза или без ключа — контейнеры не поднимутся, в логе
   `LLM_MODEL_MENTOR=…` с причиной. Исправить строку и повторить.
2. Флаг отеля. Открыть psql из того же каталога (канон входа — [subject-requests.md](subject-requests.md), §2):
   ```sh
   docker compose -f docker-compose.staging.yml --env-file .env \
     exec db sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"'
   ```
   Выполнить:
   ```sql
   UPDATE tenants SET config = jsonb_set(config, '{mentor_enabled}', 'true')
   WHERE slug = 'demo-hotel';
   ```
   Ответ `UPDATE 1`. Перезапуск не нужен: кабинет видит флаг через несколько секунд — срок
   кэша конфига (`platform/config_cache.py`, #168). Деплой
   и сид флаг не сбрасывают.
3. Кодекс. У демо-отеля уже есть вымышленный кодекс из сида — для проверки хватит его.
   Настоящий — раздел «Загрузить или обновить кодекс» ниже.
4. Проверка: войти в кабинет staging → «Наставник» → «Спросить» → вопрос по кодексу.
   Под суперадмином раздел виден сразу; под тестовой учёткой сотрудника — после галочки
   «Наставник — OpenAI» в её строке «Сотрудников» (раздел «Отметки согласия» ниже).
   Ответ приходит по словам, под ним «Источник: Статья N». Первый вопрос после сида
   дольше обычного: досчитываются векторы статей. Цена вопроса — spec 0048 §8.

## Включить на гостевой копии отеля

Только в PR 5 серии #492 (переключение): юрдокументы spec 0048 §9 готовы, у всех
сотрудников есть логины кабинета — условия spec 0048 §10, п. 5. Кодекс — проект: утверждения
основателем включение не ждёт ([spec 0072](../specs/0072-mentor-exam-rollout.md) §2). В шапке
файла кодекса — строка `Статус: проект`: сотрудники видят «Проект кодекса», а экзамен на проекте
сдаётся только пробно — в «Итоги экзаменов» не идёт («не сдан · пробно 85 %»), пока кодекс не
утвердят (spec 0072 §6, решение основателя 10.11).
Шаги те же, но все команды — из каталога копии `/home/deploy/hospitality-pilot`, а не
`/opt/hospitality` ([pilot-copy.md](pilot-copy.md)), и со `slug` отеля в SQL вместо `demo-hotel`. Кодекс загрузить сразу после флага: пока его нет, сотрудники
видят «Кодекс ещё не загружен».

Порог экзамена пилотного отеля — 80 % (spec 0072 §2). В том же psql, что флаг шага 2, до
первого экзамена:
```sql
UPDATE tenants SET config = jsonb_set(config, '{mentor_exam_pass_percent}', '80')
WHERE slug = '<slug отеля>';
```
Ответ `UPDATE 1`, перезапуск не нужен. Попытка запоминает порог при начале: экзамены, начатые
до этого шага, считаются по прежнему порогу.

## Логины всем

Экзамен — по логину кабинета, и он нужен каждому сотруднику (spec 0048 §10, п. 5). На копии
отеля листки раздают не раньше, чем готово уведомление сотрудника (PR 5 серии #492): принимая
приглашение, сотрудник соглашается с текстом на этой странице. Менеджер отеля (или основатель под
учёткой менеджера), по службе за раз:
1. «Сотрудники» → «Пригласить списком» → вставить столбец имён (до 100 строк), выбрать уровень
   и службы → «Составить список».
2. Проверить логины в таблице, вписать пустые → «Выпустить приглашения (N)». Отмеченные строки
   — поправить и нажать ещё раз: пока в списке есть ошибка, не выпущено ни одно приглашение.
3. «Печать» — по две карточки в ряд. Ссылки видны только на этом экране: страницу закрыли до
   печати — «Отозвать» эти строки в «Ожидают принятия» и выпустить заново.
4. Раздать каждому лично в день выпуска: ссылка живёт `STAFF_INVITE_TTL_HOURS` (72 часа).
   Не принятые к сроку пропадают из «Ожидают принятия» — выпустить заново.

## Отметки согласия

«Наставник» отправляет тексты сотрудника в OpenAI (США) — только по его письменному согласию,
пункт 2 бланка ([staff-notice.md](../legal/staff-notice.md)). Без отметки раздел сотруднику
закрыт, и включение флага отеля сначала не открывает его никому, кроме суперадмина
([spec 0082](../specs/0082-staff-ai-consent.md)). Менеджер отеля (или основатель под учёткой
менеджера), со стопкой подписанных бланков:
1. «Сотрудники» → в строке сотрудника, у которого в пункте 2 стоит «согласен», — галочка
   «Наставник — OpenAI». Сохраняется сразу, рядом — «Сохранено». Свою строку — тоже.
2. «Не согласен» или пункт вычеркнут — галочку не ставить: экзамен этот сотрудник сдаёт
   без кабинета, в «Итогах экзаменов» его нет — сверху строка «Без отметки согласия…» с числом.
3. Отозвал согласие — снять галочку (раздел закрывается сразу) и написать на
   privacy@necturn.com: данные удаляет основатель — [subject-requests-staff.md](subject-requests-staff.md)
   §5, блок «Наставника».

Галочки «Идеи и «Оформить» — Anthropic» — то же по пункту 3 бланка, видны при включённых
«Предложить идею» или «Служебных записках».

## Назначить экзамен

«Итоги экзаменов» считают только назначенный экзамен ([spec 0072](../specs/0072-mentor-exam-rollout.md)
§3): экзамен с темой на выбор — «Экзамен для себя», менеджер его не видит. Менеджер отеля (или
основатель под учёткой менеджера), после «Логинов всем», «Отметок согласия» и записи порога:
1. **Проба по-русски — до первого назначения «всем».** Назначить одну главу службе уборки, дать
   двум-трём горничным сдать с телефона и рядом с ними посмотреть, что они ответили и какую оценку
   поставил «Наставник»: ответ — свободный текст, а проверку модели мерит только набор evals на
   вымышленном кодексе. Его число и порог приёмки — в spec 0072 §2: порог не выполнен или промпт
   проверки либо модель «Наставника» сменились после замера — сначала прогон набора по «да»
   основателя (платный, меньше цента). Оценки «не разобралась» или явно несправедливые —
   назначение снять и сказать основателю.
2. «Наставник» → «Итоги экзаменов» → «Назначить экзамен»: тема — «Весь кодекс» или «Выбрать
   главы» (главы должностей «Для кого» — тоже главы), кому — «Всем сотрудникам» или «Службам» →
   «Назначить». Сотрудники видят строку «Вам назначен экзамен» над вкладками «Наставника».
3. Итоги — разделом назначения на той же вкладке. «Сдан однажды — сдан»: пересдача после сдачи
   результат не отнимает. Назначение не правится: «Снять» и назначить заново — итоги снятого
   пропадают со страницы, попытки остаются в базе.
4. Кодекс перезагрузили с другими главами — глава назначения ищется по номеру и названию;
   пропала — сотрудник видит «Этот экзамен сейчас не пройти» (ERR-MENTOR-006): снять и назначить
   по новому оглавлению.

## Загрузить или обновить кодекс

Менеджер отеля (или основатель под учёткой менеджера): «Наставник» → «Кодекс» →
«Загрузить кодекс» → выбрать **все** файлы кодекса (`.md`) сразу.

- Новый кодекс заменяет прежний целиком. Ошибка разметки — сообщение с файлом и строкой
  («Файл 20_front_office.md, строка 41: статья 15 вместо 14»), прежний кодекс остаётся.
- Загрузка пересчитывает векторы всех статей (цена — spec 0048 §8) из того же дневного
  бюджета наставника.
- Диалоги сотрудников и оценки «Тренировки» остаются. Отметки «Неточность в статье» остаются
  только у статей, текст которых не изменился (spec 0072 §6): исправленную статью сотрудники
  отмечают заново, если неточность осталась.
- **Утвердили кодекс** — в шапке файла `Статус: проект` заменить, например, на
  `Статус: утверждён 15.12.2026`, и загрузить заново: пометка «Проект кодекса» пропадает,
  пробные попытки в итог так и не идут. Сотрудники сдают те же назначения заново — нового
  назначения не нужно: первая же законченная попытка по утверждённой редакции сменяет «пробно».
- Какие статьи проверить первыми — «Где ошибаются» → «Неточности в статьях»: сверху статьи,
  которые отметило больше сотрудников.
- Файлы кодекса в репозиторий не кладутся: он публичный.

## Траты

- **Потолок** — `LLM_MENTOR_DAILY_BUDGET_USD` в `.env`, на отель в сутки, отдельно от
  гостевого бота. Сутки — UTC: новые начинаются в 05:00 по Алматы.
- **Потолок достигнут** — сотрудники до 05:00 видят «Наставник на сегодня ответил на все
  вопросы, что мог…» (ERR-AI-002). Гостевой бот не затронут. В канал алертов приходит
  ERR-OPS-019 с первого отказа; кончился баланс OpenAI или отозван ключ — ERR-OPS-018
  ([alerts.md](alerts.md#err-ops-018)). Гостевые ERR-OPS-006/009/010 наставник не будит.
- **Где видно расход** — копия утренней сводки основателю: «ИИ за сутки отеля: $… (гостевой
  бот $…, наставник $…)».
- **Изменить потолок** — строка в `.env` и перезапуск, как в шаге 1.
- **Дни экзамена.** Экзамен из 10 вопросов — около $0,006 ([spec 0048](../specs/0048-mentor.md)
  §12): потолок `2.0` из шага 1 — около 300 попыток в сутки, если в тот же день никто не
  спрашивает и не тренируется. Экзамен всего отеля — службы по дням (до ~250 попыток в день,
  считая пересдачи) или потолок выше на эти дни и обратно после — оба раза строкой в `.env`
  и перезапуском, как в шаге 1, на копии отеля — из её каталога (раздел «Включить на гостевой
  копии отеля») ([spec 0072](../specs/0072-mentor-exam-rollout.md) §5).

## Выключить

Тот же SQL шага 2 с `'false'`: пункт меню исчезает сразу, кодекс и диалоги остаются (их
стирает ретеншн, spec 0048 §4). Пустой `LLM_MODEL_MENTOR` тоже останавливает траты, но
сотрудники видят «Наставник сейчас не отвечает» — флаг понятнее.
