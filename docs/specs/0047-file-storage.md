# Spec 0047: хранилище файлов — общий узел

- **Статус:** в работе (PR #496)
- **Issue:** #491. Где лежат файлы, шифрование, изоляция разбора и антивирус —
  [ADR-022](../adr/ADR-022-file-storage.md); здесь устройство узла и его числа.
- **Дата:** 2026-10-27

## 1. Проблема

Фото блюд и товаров (#418), файлы гостя с реквизитами для АВР (#493) и фото к заявке (#82)
принимают файлы. Без общего узла каждое направление написало бы хранение, проверку типа и
бэкап по-своему (P-12). Экранов загрузки здесь нет — они у направлений.

## 2. Назначения

Назначение (`purpose`) задаёт правила файла. Новое назначение — строка в этой таблице и в
`FilePurpose`.

| Назначение | Что принимается | Сторона картинки | Срок хранения | Кэш браузера |
| --- | --- | --- | --- | --- |
| `menu_photo` | картинка | ≤ 960 px | пока жив товар: удаление фото — удаление файла | сутки |
| `request_photo` | картинка | ≤ 1600 px | 90 дней от загрузки — [spec 0032](0032-guest-text-retention.md) | нет |
| `guest_document` | картинка, PDF, DOCX | ≤ 2048 px | 90 дней от загрузки — [spec 0032](0032-guest-text-retention.md) | нет |

Размер загружаемого файла — до **10 МБ** у любого назначения: фото с телефона бывают 5–8 МБ,
а картинка всё равно уменьшается. У документа гостя сторона больше, чем у фото блюда, — на
2048 px текст реквизитов на листе А4 читается и бухгалтером, и моделью (#493).

## 3. Загрузка

`store_upload(purpose, data, original_name, …)` по шагам; первый отказ останавливает загрузку:

1. Пустой файл или больше 10 МБ — ERR-FILES-001 (пустой — ERR-FILES-002).
2. Тип — по первым байтам, не по расширению и не по `Content-Type`: JPEG `FF D8 FF`, PNG
   `89 50 4E 47`, WebP `RIFF….WEBP`, PDF `%PDF-`, DOCX — ZIP `PK\x03\x04`. Не из белого списка
   назначения — ERR-FILES-002.
3. Разбор — в дочернем процессе (ADR-022 п. 3): потолок памяти 1 ГБ, процессора 10 с, общий
   таймаут 15 с, не больше двух одновременных разборов на процесс приложения.
   - **Картинка** перекодируется в WebP (качество 85): поворот по EXIF, уменьшение до стороны
     назначения, без метаданных. Больше 50 Мп, не декодируется, таймаут — ERR-FILES-003.
   - **DOCX** — в оглавлении ZIP обязаны быть `[Content_Types].xml` и `word/document.xml`
     (иначе ERR-FILES-002); `vbaProject.bin` или тип `macroEnabled` — ERR-FILES-004.
   - **PDF** хранится как есть: не разбирается вовсе.
4. Шифрование AES-256-GCM (ADR-022 п. 2): `0x01 ‖ nonce(12) ‖ шифротекст+тег`, дополнительные
   данные — ключ хранения. Нет ключа — ERR-FILES-006.
5. Ключ хранения — `{tenant_id}/{purpose}/{file_id}.{webp|pdf|docx}`: тенант в ключе — вторая
   стена к RLS метаданных. Запись в хранилище, затем строка `uploaded_files` в той же
   транзакции; сбой после записи файла — файл удаляется.

`original_name` — только последний сегмент пути, без управляющих символов, ≤ 255 символов;
нужен бухгалтеру и как имя при скачивании.

## 4. Чтение и отдача

`read_file(file_id) -> StoredFile`: строка ищется под RLS (чужой id — ERR-FILES-005, как
несуществующий), ключ обязан начинаться с тенанта из контекста, файл расшифровывается. Файла в
хранилище нет или он не расшифровался — ERR-FILES-007.

`file_response(stored)` — единственный способ отдать файл в HTTP. Всегда:
`X-Content-Type-Options: nosniff`, `Content-Security-Policy: default-src 'none'; sandbox`.
Картинка — `inline` (для `<img>` на своих страницах), PDF и DOCX — `attachment` с именем
`original_name` (RFC 5987). `Cache-Control`: `private, max-age=86400` для `menu_photo`,
`no-store` для остальных. Маршрут, право и тенант страницы проверяет направление (#418, #493).

## 5. Удаление и ретеншн

Удаление жёсткое: сначала файл в хранилище (идемпотентно), потом строка. Мягкого удаления
(`deleted_at`) нет — строка с `original_name` сама ПД. `delete_file(file_id)` — для владельца
файла (снятое фото блюда). Ретеншн: `delete_expired_files(created_before)` удаляет файлы
назначений со сроком spec 0032; зовёт её джоба `channels/common/retention.py` шагом 6 —
`menu_photo` не трогается. Нечего удалять — к хранилищу не обращается.

## 6. Бэкап и окружение

- Том `files_data` → `/var/lib/hospitality/files` у `app` и `worker` в обоих compose; каталог
  в образе создан от `appuser` — том наследует владельца. `FILE_STORAGE_ROOT` задан в образе.
- `backup.sh`: после дампа — `tar` тома одноразовым контейнером `app`, проверка `tar -t`,
  шифрование age, `<метка>-<время>.files.tar.age` рядом с дампом; тот же ретеншн каталога.
  Оба файла получают боевые имена вместе: упал любой шаг — нет ни одного, и алерт о свежести
  бэкапа (ERR-OPS-008) срабатывает как раньше.
- `/health/ready` проверяет, что корень тома доступен на запись.

## 7. Контракты

- **Порт** `shared/ports/file_storage.py`: `put(key, data)`, `get(key) -> bytes`
  (`StoredObjectNotFoundError`), `delete(key)` (идемпотентно), `check_health() -> bool`;
  негодный ключ — `ValueError`. Тип содержимого порт не принимает: хранит он шифротекст.
- **Адаптеры** `integrations/file_storage/`: `FakeFileStorageAdapter` (память),
  `LocalDiskFileStorageAdapter` (файлы `0600`, путь не выходит из корня); выбор —
  `FILE_STORAGE_BACKEND=local|fake`, корень — `FILE_STORAGE_ROOT`.
- **Сервис** `platform/files.py`: `store_upload`, `read_file`, `delete_file`,
  `delete_expired_files`, `file_response`; подключение адаптера — `configure_file_storage`
  из `app.py` и `worker.py`.
- **Таблица** `uploaded_files` (миграция 0036, канон RLS 0002): `id`, `tenant_id`, `purpose`,
  `storage_key` (unique), `content_type`, `size_bytes`, `sha256` (хранимого открытого
  содержимого), `original_name`, `uploaded_by_user_id` (FK `users`, SET NULL),
  `guest_identity_id` (без FK — ядро не ссылается на таблицы модулей), `created_at`.
- **Метрики:** `file_uploads_total{purpose,outcome}`, `file_storage_errors_total{operation}`.

## 8. Ошибки

| Код | HTTP | Когда |
| --- | --- | --- |
| ERR-FILES-001 | 413 | больше 10 МБ |
| ERR-FILES-002 | 415 | тип не из белого списка назначения, пустой файл, ZIP не DOCX |
| ERR-FILES-003 | 422 | картинка не декодируется, больше 50 Мп, разбор не уложился в лимиты |
| ERR-FILES-004 | 422 | DOCX с макросами |
| ERR-FILES-005 | 404 | файла с таким id у отеля нет |
| ERR-FILES-006 | 503 | хранилище не подключено или нет `FILE_ENCRYPTION_KEY` |
| ERR-FILES-007 | 503 | файл пропал из хранилища, не расшифровался или сбой записи/чтения |

Статьи — [errors.md](../runbooks/errors.md). Гость видит текст на своём языке — экран #493.

## 9. Тесты

Контракт порта на обоих адаптерах; PNG с EXIF → WebP ≤ стороны назначения без EXIF; JPEG с
поворотом EXIF → повёрнут; текст с расширением `.jpg` → 002; SVG → 002; DOCX с `vbaProject.bin`
→ 004; 11 МБ → 001; картинка больше 50 Мп → 003; ключ содержит тенант; на томе — шифротекст;
чужой тенант не читает и не удаляет файл по id, UPDATE/DELETE без WHERE его не задевают;
ретеншн удаляет файл и строку `guest_document`, не трогает `menu_photo`; заголовки отдачи;
`backup.sh` кладёт архив тома рядом с дампом, а упавший `tar` не оставляет ни одного файла.

## 10. Что сознательно не делаем

S3-адаптер и антивирус (ADR-022); превью PDF в браузере; HEIC (iPhone отдаёт в браузер JPEG);
приём файлов из Telegram (#82 — LATER); экраны загрузки и маршруты отдачи — у направлений.
