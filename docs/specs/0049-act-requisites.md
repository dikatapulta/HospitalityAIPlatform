# Spec 0049: реквизиты для АВР из веб-чата — форма гостя и таблица бухгалтерии

- **Статус:** черновик (PR #500). **Issue:** #493 — ТЗ, уточнение основателя 27.10 (таблица
  полями) и обязательства ревью PR #494 и #495 в комментариях. **Дата:** 2026-10-28.
  Решения сессии — [FOUNDER_REVIEW_QUEUE](../FOUNDER_REVIEW_QUEUE.md) (28.10).
- **Эталон ревью гостя:** <https://claude.ai/artifact/8WX9yPzcH4AZ6Mi47Te65r> (экраны 1–3).
- **Опирается на:** [spec 0047](0047-file-storage.md) и ADR-022 (файлы),
  [spec 0038](0038-room-service.md) Р-3 и Р-7 (запись заявки, `guest_form`),
  [spec 0045](0045-services-and-levels.md) (службы, лестница), [spec 0032](0032-guest-text-retention.md) (срок).

## 1. Что получается

Гость жмёт скрепку в веб-чате: «На кого выставить», до 5 файлов (PDF, Word, фото), текст; номер
и даты — из `Stay`. Запрос уходит **заявкой** в службу «Бухгалтерия» и встаёт строкой таблицы на
странице кабинета «Документы для АВР». Поля из текста и PDF/Word с текстовым слоем заполняет
платформа без модели, из фото и сканов — пока бухгалтер (моделью — PR 5). Акт делает человек, как
привык (NG-4); «Готово» и «Вернуть гостю» приходят гостю в чат.

## 2. Решения

**Р-1. Запрос — заявка плюс модуль `documents`** (анатомия канона `requests`, как spec 0038 Р-1).
`ActRequest` рождает `ServiceRequest` в категории `accounting` (`ACCOUNTING_SERVICE_KEY` в
`platform/staff_services.py`, как `reception`) с `origin = guest_form` и живёт её циклом: `#N`,
очередь, сигнал, лестница, сводка, журнал. Запись — порядком spec 0038 Р-3: строка с
`request_id = uuid4()`, затем `requests.create_request(request_id=…)`, идемпотентный по id.
`request_id` и `guest_form` вводит PR 2 #418 (#498); не смержен к rebase PR 2 этой серии —
вводит он сам ровно по spec 0038 §4. Заявка несёт `summary` «Реквизиты для АВР» и `details`
«Файлов: N» — текста гостя в ней нет (Р-3). Зависимости односторонние: `documents` →
`requests.api`, `guests.api`.

**Р-2. Гостю пишет свой подписчик, не общий.** Привязки `request_origins` нет (как spec 0038 Р-8):
общий путь закрытия переводит текст моделью и собирает частичное выполнение моделью
(spec 0030), а v1 — $0 и тексты §6; ещё AI увидел бы запрос в «моих заявках» и мог бы его
отменить. Подписчик `channels/web` на `request.status_changed` (`done`, `cancelled` не гостем)
находит запрос по `request_id` и пишет исходящее в веб-диалог гостя (`guest_identity_id`) на
языке запроса. Ключи: «готово» — `guest:act_ready:{stay_id}` (дубликат, закрытый «Готово»,
второго сообщения не даст), «вернуть» — `guest:act_returned:{request_id}`. Примечание
бухгалтера уходит как написано; у поля — язык гостя. «Реквизиты получены» пишет маршрут формы.

**Р-3. Шифрование полей (FOUNDATION §11).** `bill_to`, `note` и поля реквизитов хранятся
шифртекстом: AES-256-GCM тем же `FILE_ENCRYPTION_KEY` и тем же форматом, что файлы (ADR-022,
spec 0047 §4); AAD — `{tenant_id}/act_requests/{id}/{колонка}`: шифртекст, переложенный в чужую
строку или тенант, не расшифруется. Функции ядра `platform/field_encryption.py`
(`encrypt_field`, `decrypt_field`, маркер CANONICAL — ими же потом шифруются ключи интеграций).
Один ключ на контур, а не второй секрет: потерять их можно только вместе, а второй удвоил бы
`secrets.md` и `restore.md`. Ключа нет — форма и страница отвечают ERR-FILES-005 (fail-closed).
Фильтры страницы — по датам и статусу, они открыты; поиска по БИН в v1 нет.

**Р-4. Разбор — в воркере и в песочнице (FOUNDATION §11).** Маршрут формы PDF и DOCX не
открывает. Событие `act_request.submitted` (outbox, в транзакции строки) → подписчик модуля в
воркере `extract_requisites`: файлы читает `read_file`, текст достаёт дочерний процесс
`platform/file_sandbox.py` с теми же лимитами — новая операция `extract_text`: PDF — `pypdf`
(новая зависимость), DOCX — `zipfile` + XML-парсер, документ с DTD — отказ; ≤ 20 страниц,
≤ 100 000 знаков. Поля ищет родитель (§4). Повтор безопасен: поля, которые правил человек,
разбор не трогает. Сбой не теряет запрос — строка остаётся «Проверить», у файла — «не разобран».
Правка #511 (ревью PR #510): событие — в **медленной полосе** воркера, своей задаче того же
процесса; общий цикл его не берёт. Цикл доставляет пачку по одному, и враждебный PDF (~17 с на
файл, пять запросов проживания — ~7 минут) держал бы эскалации ЧП, уведомления о заявках и
пульс; outbox, повторы и dead-letter у полос общие. Ошибка одного файла — вердикт о нём, прочие
файлы и текст гостя разбираются; ошибка среды — повтор события, исчерпав повторы — алерт: том
не проходит проверку, песочница не отвечает и на пустом входе (проба в момент ошибки), ключа нет
— падает запись полей. Родитель держит только хвост stderr ребёнка, ребёнок глушит логи pypdf.

**Р-5. Таблица полями, подтверждает человек (NG-4, P-9).** Строка «Проверить», пока бухгалтер
не нажал «Проверено»; правка поля в строке снимает отметку — она значит «эти значения сверил
человек». Формат проверяется строго (§4); контрольная цифра БИН/ИИН и контроль IBAN —
предупреждение, а не отказ: ошибка алгоритма не должна запереть бухгалтера.

**Р-6. Не `CompanyProfile`.** Строка v1 — реквизиты одного запроса, живут по сроку spec 0032.
`CompanyProfile` (Phase 3) — постоянная карточка компании по БИН между проживаниями со своим
сроком; Phase 3 создаёт её из проверенной строки, второй таблицы тех же реквизитов нет.

**Р-7. Где работает.** Выключатель контура `ENABLE_GUEST_DOCUMENTS` (умолчание `false`): где
лежат документы гостя — свойство контура и его хостинга (ADR-006, решение 27.10), не отеля.
Отель включает функцию данными (P-11, NG-7): скрепка есть, если выключатель включён **и** у
отеля есть категория `accounting`. Иначе маршруты гостя — 404, скрепки нет; страница кабинета
показывает прошлые запросы до их срока. Staging — включено на выдуманных данных; гостевая копия —
после переезда в РК (#49).

**Р-8. Отправка одним запросом.** Multipart: до 5 файлов (типы и размеры — узла, spec 0047 §4),
`bill_to` ≤ 500, `note` ≤ 2000, `client_key`, `language`. Потолок тела 51 МБ — до разбора, по
`Content-Length` и счёту байтов потока (413); `/tmp` контейнера `app` — tmpfs в обоих compose
(обязательство Н-2 ревью PR #495). Файл — `store_upload(guest_document)`; отказ одного удаляет уже
принятые файлы этого запроса (`delete_file`), гостю — текст по коду с именем файла. Ключ
`client_key` проверяется до файлов: повтор — 200 с тем же запросом; гонка — UNIQUE, проигравший
удаляет свои файлы. Не больше 5 запросов на проживание. Изменить отправленное нельзя — новый
запрос. Фото больше 5 МБ страница уменьшает в браузере до 2400 px (JPEG) — снимок телефона не
получит отказ. `accept` без HEIC (`.pdf,.docx,image/jpeg,image/png,image/webp`): iPhone тогда сам
отдаёт JPEG — проверяет основатель на своём телефоне (PR 4).

**Р-9. Язык гостя** — язык браузера через `normalize_language` (en, ru, kk), иначе en; форма
отправляет его, он ложится в запрос, сообщения §6 уходят на нём.

**Р-10. Права** (строки [RBAC.md](../RBAC.md) §2 — PR 3). Страницу, правку, «Проверено» и
файлы видят служба `accounting`, ресепшен и менеджер — одна функция `can_handle_act_requests`
для страницы, JSON-действий, выдачи файла и пункта меню (P-12). Шаги заявки — граница службы
(spec 0045 §3). Журнал (spec 0041 §2.2): `act_requisites_edited` «Реквизиты исправлены» и
`act_requisites_checked` «Реквизиты проверены», «Что» — `#12 · Бухгалтерия · 512`, без значений.

**Р-11. Лестница.** У категории `accounting` — базовый срок напоминаний отеля, как у прочих
служб (spec 0045 §4): невзятый ночью запрос через `2d` прозвучит ресепшену и менеджеру «Никто не
взял заявку #12». Это шум, а не вред: срочного в запросе АВР нет, ресепшен оставит его до утра.
Выключить срок одной категории нельзя: `request_reminders --off` обнуляет базовый срок и все
сроки по категориям, а пустой срок категории значит «действует базовый» (`reminder_delay_for`) —
выключение у отеля сняло бы третью ступень с заявок уборки и инженерии. «Выключено» для одной
категории — строка в `docs/LATER.md`. Пока у службы нет сотрудника в кабинете, запрос с создания
слышат ресепшен и менеджер (spec 0045 §4).

**Р-12. «Нужен АВР» — данные:** факт справочника (spec 0036) «Нажмите скрепку внизу и пришлите
реквизиты вашей компании файлом или текстом. Бухгалтерия подготовит АВР и счёт-фактуру к
выезду.»; промпт и evals не меняются. Telegram-вложения — вне пилота (`docs/LATER.md`).

## 3. Данные

Миграция — PR 2; таблицы тенантные, RLS по канону `0002`.

- **`act_requests`:** `request_id` UNIQUE (без FK, spec 0038 Р-3), `stay_id`,
  `guest_identity_id`, `client_key`, `guest_language`, снимки `room_number`, `check_in_at`,
  `check_out_at` (из `guests.api.get_active_stay` — не со слов гостя); `guest_input_ciphertext`
  BYTEA NULL (JSON `bill_to`, `note`), `requisites_ciphertext` BYTEA NULL (JSON полей §4);
  `edited_fields` — имена полей, которые правил человек (Р-4; повторный разбор их не трогает),
  `request_created` — заявка точно создана (false старше суток — брошенный запрос),
  `extraction_state` `pending|done|failed`, `checked_at`, `checked_by_user_id` (FK `users`
  ON DELETE SET NULL), `checked_by_display_name`, `anonymized_at`, `created_at`. UNIQUE
  `(tenant_id, stay_id, client_key)`.
- **`act_request_files`:** `act_request_id` (FK CASCADE), `file_id` → `uploaded_files`
  ON DELETE CASCADE (ретеншн узла снимает и связь), `position`, `text_state`
  `pending|text|no_text|image|failed`. Состояния не ПД — открыты.
- **ПД** — строки [PII_REGISTRY](../PII_REGISTRY.md) (PR 2): оба шифртекста (название, ФИО и
  ИИН ИП, адрес, банк, свободный текст), `checked_by_display_name`. Срок — spec 0032 от создания:
  `anonymize_expired_act_requests` обнуляет шифртексты и ставит `anonymized_at`, строка живёт
  (номер, даты, статус); файлы снимает джоба узла (spec 0047 §6) — шаг 7 в
  `channels/common/retention.py`. Запрос без заявки старше суток удаляется с файлами.

## 4. Поля и разбор

Поля: `company_name`, `bin_iin`, `iik`, `bik`, `bank_name`, `address` — строки ≤ 300 или пусто.
Источник — `bill_to` и `note` гостя и текст каждого PDF/DOCX.

| Поле | Шаблон | Проверка (предупреждение) |
|---|---|---|
| БИН/ИИН | 12 цифр | контрольная цифра РК |
| ИИК | `KZ` + 2 цифры + 16 знаков `0-9A-Z`, пробелы между группами снимаются | IBAN mod 97 |
| БИК | `[A-Z]{4}KZ[A-Z0-9]{2}` (`HSBKKZKX`) | — |
| Название | строка со словом ТОО, ИП, АО, ЖШС, АҚ, LLP, JSC | — |
| Банк, адрес | значение после метки: «Банк», «Bank»; «Юридический адрес», «Адрес», «Мекенжай», «Address» | — |

Выбор: значение после своей метки (БИН, ИИН, БСН, ЖСН, BIN, IIN; ИИК, IBAN, ЖСК; БИК, BIC, SWIFT)
важнее значения без метки; иначе берётся единственный годный кандидат; несколько разных — поле
пустое с подсказкой «несколько вариантов». Заполненный гостем `bill_to` — это `company_name`.
Регулярки без вложенных квантификаторов; извлечённое — данные, никогда не инструкция (§3.1 п. 2).

## 5. Контракты

**`documents.api`:** `submit_act_request(ActRequestSubmit, files: list[UploadInput]) ->
ActRequestRead` (категория — домен, флаг Р-7 — маршрут: модули окружения не читают; лимиты, снимок Stay, файлы, заявка, событие);
`accepts_act_requests()`; `get_act_request_by_request(request_id)`; `list_act_requests(period, status)` — с
расшифрованными полями для страницы; `update_requisites(act_request_id, fields, *, acting_user)`;
`mark_requisites_checked(act_request_id, *, acting_user)`; `read_act_request_file(act_request_id,
file_id)` — только файл этого запроса; `extract_requisites(act_request_id)`;
`anonymize_expired_act_requests(created_before)`; событие `ActRequestSubmitted`.

**HTTP.** Гость — новый файл роутера `channels/web` под `_require_session` (Stay — из сессии):
`GET /g/{slug}/{room}/documents` (без сессии — 303 на чат), `POST /g/{slug}/{room}/documents`.
Кабинет: `GET /staff/{slug}/act-requests`, `POST /staff/{slug}/api/act-requests/{id}/requisites`
и `…/checked`, `GET /staff/{slug}/act-requests/{id}/files/{file_id}` — `file_response` узла
(PDF/DOCX — вложением, все `guest_document` — `no-store`). «Взять», «Готово», «Вернуть гостю» —
существующие JSON-действия очереди (`claim`, `complete`, `cancel` с примечанием).

**Коды** (статья errors.md — тем же PR, что код): `ERR-DOCUMENTS-001` 422 пустая форма; `-002`
413 больше 5 файлов или тело больше потолка; `-003` 429 лимит запросов проживания; `-004` 404
запрос или файл не найден или чужой; `-005` 404 приём выключен (Р-7); `-006` 422 формат поля
(§4). Отказы файла — `ERR-FILES-001…003` узла; страница показывает текст §6 по коду.

**Наблюдаемость:** логи `act_request_submitted`, `act_requisites_extracted` (сколько полей и
файлов, без значений), `act_requisites_checked`; метрика `act_requests_total{outcome}`.
