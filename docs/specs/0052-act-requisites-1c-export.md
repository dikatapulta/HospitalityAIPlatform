# Spec 0052: выгрузка реквизитов для 1С со страницы «Документы для АВР»

- **Статус:** принята в PR #541. **Issue:** #517. **Дата:** 2026-10-29.
- **Опирается на:** [spec 0049](0049-act-requisites.md) (строки, «Проверено», права Р-10),
  FOUNDATION §8 (порт `AccountingPort`, правило 5 — упрощённый адаптер), ADR-007 (Fake).
- Решения сессии — [founder-review](../founder-review/2026-10-29-pr541-1c-export.md).

## 1. Проблема

Страница «Документы для АВР» показывает реквизиты строкой и копирует значение нажатием
(spec 0049 §6), но бухгалтер всё равно переносит в карточку контрагента 1С шесть полей
руками. Слово основателя 28.10: «а может сразу формат, который они смогут в 1С
импортировать?»

## 2. Решения

**Р-1. Формат — Excel (.xlsx), строка — контрагент.** Загружается обработкой загрузки
из табличного документа 1С 8.3: колонки сопоставляются один раз, настройку 1С помнит.
Подходит почти к любой конфигурации. XML обмена 1С (EnterpriseData) загружался бы без
сопоставления, но зависит от конфигурации и версии — без доступа к их 1С это гадание
(issue #517, вариант «б»); он — второй адаптер того же порта, если понадобится.

**Р-2. Только строки «Проверено».** В 1С уходит то, что сверил человек (spec 0049 Р-5),
а не черновик разбора. Не попадают и обезличенные строки (значений нет, spec 0032), и
запросы, которые бухгалтерия вернула гостю (гость пришлёт заново). Период — даты фильтра
страницы; отметку «Статус» фильтра выгрузка не читает. Дублей не схлопывает: два
проживания одной компании — два акта, а повтор БИН 1С найдёт сама поиском по БИН/ИИН.

**Р-3. Колонки** — в порядке карточки контрагента 1С и страницы: Контрагент · БИН/ИИН ·
Адрес · ИИК · БИК · Банк; затем Номер · Заезд · Выезд (дни отеля, `дд.мм.гггг`) — к какому
проживанию акт, их бухгалтер не сопоставляет. Все ячейки — текст: БИН с ведущим нулём цел,
значение «=…» из реквизитов гостя — строка, не формула. Лист «Контрагенты», имя файла —
«Контрагенты для 1С 01.10.2026–29.10.2026.xlsx».

**Р-4. Порт, а не код в модуле** (FOUNDATION P-3, §8). `shared/ports/accounting.py` —
`AccountingPort.export_counterparties(rows, *, period_from, period_to) -> ExportFile`;
адаптеры — `integrations/accounting/`: `OneCXlsxAccountingAdapter` (Р-1, без сторонних
библиотек — книга собирается `zipfile` и XML) и `FakeAccountingAdapter` (справочник «1С»
в памяти по БИН/ИИН, файл — JSON той же таблицы). Composition root (`app.py`) кладёт
Excel-адаптер всегда: он внешней системы не трогает и работает и локально, и на контуре;
выбор конфигурацией тенанта (§8 правило 3) — когда появится второй адаптер.

**Р-5. Права** — как у страницы: `can_handle_act_requests` (spec 0049 Р-10, RBAC.md §2).

**Р-6. След.** Выгрузка ничего не меняет — в журнал изменений (spec 0041) не пишется;
лог `act_requisites_exported` (исход, число строк, адаптер, `user_id`, без значений),
как у выдачи файла гостя. Метрика `act_requisites_exports_total{tenant_id,outcome}`.
Файл не хранится: собирается в памяти, ответ — вложением, `no-store` (PII_REGISTRY,
«Вне БД платформы»).

## 3. Контракты

**`documents.api`:** `export_checked_requisites(*, created_from, created_before,
period_from, period_to, zone, acting_user) -> RequisitesExport` — исход
`exported | empty | too_many` (больше `EXPORT_LIMIT` = 1000 строк), файл — только у
`exported`. Нет ключа шифрования — ERR-FILES-005 от `list_act_requests`.

**HTTP:** `GET /staff/{slug}/act-requests/export?from&to[&status]` — вторая кнопка формы
фильтра (`formaction`). Файл — `200` вложением; `empty`, `too_many` и нет ключа — `303`
на страницу с теми же датами (и `export=<исход>` — пояснение). Новых кодов ошибок нет.

**Тексты страницы:** кнопка «Скачать для 1С»; подсказка «„Скачать для 1С“ — Excel-файл для
загрузки контрагентов в 1С: только строки «Проверено» за выбранные даты.»; `empty` — «За
эти даты нет строк «Проверено» — выгружать нечего.»; `too_many` — «Строк «Проверено» за
эти даты больше 1000 — сузьте даты.»

## 4. Тесты

- Контракт порта на оба адаптера (`tests/test_accounting_port.py`): порядок и ровно эти
  строки, пустой список — заголовок, текст как есть (формула, ведущий ноль, пробелы),
  управляющие символы выброшены, имя с периодом. Excel: все ячейки `t="s"`, формул нет,
  части — корректный XML, байты воспроизводимы, столбцы после Z.
- Модуль (`documents/tests/test_export.py`): только «Проверено» своего отеля, новые сверху;
  правка после «Проверено», возврат гостю и обезличивание — вне файла; даты — дни отеля;
  потолок — `too_many`.
- Кабинет (`staff_portal/tests/test_act_requests_export.py`): бухгалтер скачивает .xlsx
  (`no-store`, вложение) с проверенной строкой; нет строк — 303 с пояснением; служба без
  `accounting` — 403.

## 5. Проверка у отеля и вне основы

Бухгалтер загружает файл с выдуманными компаниями (собран этим адаптером) в копию своей базы
1С — контрагент заводится без правки руками; сделать это может только отель (основатель там
работает). Ответ основателя 29.10: в бухгалтерии «1С:Предприятие 8.3».
Вне основы: Кбе (в данных его нет — `docs/LATER.md`, Н-9 ревью PR #500); банковский счёт
контрагента в 1С — отдельный справочник, его загрузка зависит от обработки; XML обмена;
выгрузка АВР.
