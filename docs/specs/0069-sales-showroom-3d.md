## 1. Проблема

Группы на 30–40 человек подбирают турагенты и корпоративные клиенты из-за рубежа, не видя здания:
отдел продаж шлёт PDF и фото, агент спрашивает «а с какого этажа видно горы?» письмами. Нужна
витрина, где агент сам смотрит здание, этажи, стороны и номера, подбирает их словами («высокий этаж с
видом на Кок-Тобе, двенадцать номеров») и отправляет запрос — а отдел продаж получает его карточкой,
как любую заявку. Ограничения, которые задают форму, — тело issue (NG-7, NG-2, P-9, шлюз, ПД агентов).

## 2. Решение

### 2.1. Модуль `showroom` и сцена — данные тенанта (NG-7, P-11)

Доменный модуль `modules/showroom/` (анатомия канона `requests`) владеет **сценой** и **групповыми
запросами**. Зависимость односторонняя: `showroom` → `requests.api` (карточка), как у `table_booking`.
Имя `showroom`, а не `showcase`: `tools/demo_showcase*` — скрипты демо к показу, это другое.

**Сцена** — один документ JSON на тенанта, таблица `showroom_scenes`, не конфиг: конфиг тенанта
читается на каждом ходу гостя, а сцена на 350 номеров — десятки килобайт. Просмотрщик общий и
параметрический: строит здание из чисел сцены (корпус, этажи, номера по сторонам), файла модели нет.
Схема (`SceneDocument`, `extra="forbid"`, JSON ≤ 512 КБ, ≤ 2000 номеров):

```python
class Building(BaseModel):
    floors_total: int                       # 1..60
    length_m: float; width_m: float         # корпус — прямоугольник
    orientation_deg: int                    # азимут длинной оси; стороны считаются от него
    rounded_ends: bool = False; facade_step: bool = False   # закруглённые торцы, фасад «гармошкой»
    podium_floors: int = 0; crown: bool = False
class SideInfo(BaseModel):   names: LocalizedText; view_keys: tuple[str, ...] = ()
class ViewInfo(BaseModel):   names: LocalizedText; azimuth_deg: int | None = None; distance_m: int | None = None
class RoomTypeInfo(BaseModel): names: LocalizedText; windows: Literal[1, 2] = 1; note: LocalizedText | None = None
class Room(BaseModel):       number: str; side: Literal["north", "east", "south", "west"]; type_key: str; view_keys: tuple[str, ...] = ()
class Floor(BaseModel):
    number: int; kind: Literal["rooms", "lobby", "restaurant", "offices", "technical", "monthly", "closed"]
    sellable: bool = False; label: LocalizedText | None = None; rooms: tuple[Room, ...] = ()
class SceneDocument(BaseModel):
    schema_version: Literal[1] = 1
    building: Building; sides: dict[str, SideInfo]; views: dict[str, ViewInfo]
    room_types: dict[str, RoomTypeInfo]; floors: tuple[Floor, ...]
```

Проверки схемы: номера уникальны, `type_key`, `view_keys` и `side` — из словарей сцены, `number`
этажа — в пределах `floors_total`, продаваемый этаж (`sellable`) — только `kind = rooms`. Ни имён, ни
занятости, ни цен в сцене нет и быть не может (схема их не знает). Сцену загружает менеджер в кабинете
файлом JSON («Загрузить сцену»); новая версия заменяет прежнюю (`scene_version + 1`), действие журнала
`showroom_scene_replaced` (spec 0041 §2.2). Файлы пилотного отеля — вне репозитория (`*.local`); в
репозитории — вымышленное здание демо-тенанта для staging (PR 3).

### 2.2. Где видно: кабинет всегда, публичная страница — флагом после письменного «да» отеля

- **Кабинет** `/staff/{slug}/showroom` — менеджер и служба продаж (`category_key` конфига, §2.5):
  просмотрщик, помощник, «Загрузить сцену» (только менеджер). Пункт меню «3D-витрина» занимает
  место демо-ссылки «3D-модель ↗» (#792): модуль включён — ссылки `DEMO_3D_URL` в меню нет.
- **Публичная страница** `/showroom/{slug}` — без входа, та же страница без загрузки сцены и с формой
  запроса. Открыта, только когда `public_enabled` (§2.5): флаг ставит основатель через
  `mutate_tenant_config` после письменного «да» отеля о публикации планировки — шаг рунбука
  онбординга (PR 5). Иначе — 404 `ERR-SHOWROOM-001`, как и без сцены.
- Страница — один HTML без сборки (инлайн CSS/JS, канон spec 0027 §3.4): просмотрщик `viewer.js` и
  библиотека three.js (MIT, версия закреплена) отдаются своими статическими файлами из пакета
  `channels/showroom/assets/`, как обои чата (`wallpaper.py`): кэш навсегда, версия в адресе — хэш
  содержимого. CSP `default-src 'self'`; ничего извне не грузится, cookies и аналитики нет
  (ADR-019: иначе — поверхность данных посетителей). Надписи — en, ru, kk (en первым: агенты
  из-за рубежа); ответы помощника — на языке фразы агента.
- «Свободно / занято» на странице нет нигде (NG-2, правило 9): наличие и цены уточняет отдел продаж,
  и страница говорит это прямо (§5). Демо-занятость прототипа в продукт не переносится.

### 2.3. Навигация: сначала правила, потом модель через шлюз инструментом

`POST /showroom/{slug}/navigate` (и `/staff/{slug}/showroom/navigate` под сессией кабинета),
тело `{text ≤ 300 знаков, language?}` → `{commands, reply, source}`. Композиция — `ai/showroom/`
(как `ai/mentor`); модуль `showroom` модели не знает (FOUNDATION §5.1).

1. **Правила без модели** (`ai/showroom/rules.py`): «этаж 15 / floor 15 / 15-қабат», «номер 1507 /
   room 1507», «горы / mountains / тау», «город / city / қала», «сверху / top / жоғарыдан», «с улицы /
   street / көшеден», «выше / ниже», «сначала / reset» — ru, en, kk. Совпало — команды без вызова
   модели, `source = rules`. Это и запасной путь (§7.8): модель выключена или бюджет исчерпан —
   правила и кнопки, текст «Помощник отдыхает…» (§5), не ошибка.
2. **Модель** — `gateway.complete(purpose="showroom", forced_tool="navigate_showroom",
   max_tokens=300)`: назначение `showroom` в `purposes.py` (ADR-024 §1: своя модель
   `LLM_MODEL_SHOWROOM` — пусто = выключено на деплойменте, на staging — модель гостя, основатель
   хочет Sonnet; свой дневной бюджет тенанта `LLM_SHOWROOM_DAILY_BUDGET_USD`, умолчание $1).
   Системный промпт `showroom_navigate_v1` — инструкция и **сводка сцены** (этажи с их назначением,
   стороны и виды, типы номеров; не список 350 номеров — поиск по условиям делает код). Фраза агента —
   недоверенный ввод (§7.6): модель отвечает только аргументами инструмента, свободного текста нет.
3. **Инструмент `navigate_showroom`** (`ai/tools/navigate_showroom.py`, канон `create_service_request`;
   класс `auto` — информация, побочных эффектов нет, P-9):

   ```python
   Command = FocusFloor(floor) | FocusRoom(room) | SetView(preset: mountains|city|top|street)
           | FindRooms(floor_from?, floor_to?, side?, view_key?, type_key?, count? 1..60) | OpenRequestForm()
   class Navigation(BaseModel):
       commands: list[Command] = Field(max_length=4)
       reply: str = Field(max_length=200)      # на языке агента; без цен, наличия и обещаний
   ```

   `FindRooms` исполняет сервис ядра `showroom.api.find_rooms(RoomQuery)` — тот же, что у панели
   фильтров на странице (P-5: ИИ ничего не умеет эксклюзивно). Этаж или номер вне сцены — команда
   отбрасывается с логом `showroom_command_dropped`, остальные идут. `reply` с валютой или числом
   с «тг/₸/$/€/USD» заменяется статическим «Подобрал варианты — смотрите на модели» (неправда клиенту
   дороже пустой реплики); evals стерегут это раньше (§7).
4. **Лимиты** (канон spec 0023, ступень по IP — spec 0027 §3.3, адрес — `shared/clientip.py`):
   `showroom_navigate_ip` 30 за 10 минут на адрес, `showroom_navigate_tenant` 600 в сутки отеля (правила
   и модель вместе); выше — 429 `ERR-SHOWROOM-003`. Деньги держит бюджет назначения: при $2/$10 за 1M
   токенов (прайс-лист шлюза) вызов стоит ≈ $0,005 — около 200 вызовов модели в день на $1.
   Ошибки шлюза ERR-AI-001/002/003/006 — путь 1, не 5xx.
5. Фразы агентов не хранятся (ПД нет — хранить нечего); в логах — `tenant_id`, `source`, виды команд.
   Метрика `showroom_navigations_total{source=rules|model|fallback}`.

### 2.4. Запрос в отдел продаж — заявка в службе продаж, контакты в модуле

Форма на публичной странице: компания, контактное лицо, телефон, почта, размер группы (1–500),
даты заезда и выезда (до 400 дней вперёд), выбранные на модели номера (только из сцены, ≤ 60),
пожелания (≤ 500), язык, строка согласия (§2.6). `POST /showroom/{slug}/requests` →
`showroom.api.create_group_request(GroupRequestCreate)` — идемпотентно по `client_key`:

- строка `showroom_group_requests` (§3) и `ServiceRequest` в службе `category_key` с
  `origin = showroom_form` (новое значение `ServiceRequestOrigin`, влезает в VARCHAR(16)): запрос
  агента — не гость, поэтому он **не входит ни в числитель, ни в знаменатель** доли «без участия
  ресепшена» — одна строка в spec 0035 §4 тем же PR;
- `details` заявки — компания, размер группы, даты, номера; **контактов в заявке нет**: карточка берёт
  их из модуля (`group_requests_for_requests`, как `bookings_for_requests` spec 0064) — у контактов
  один срок хранения (§3), а не два;
- дальше — обычный цикл заявки: номер `#N`, очередь службы продаж, сигнал, пуш (spec 0050), лестница
  невзятой заявки (spec 0045 §4). Отдел продаж отвечает агенту сам — телефоном или почтой, вне
  платформы; «Готово» на карточке — «ответили». Бронь, цены, депозит — только человек в Opera (P-9,
  NG-2, NG-4); исходящей почты агенту нет;
- лимиты: `showroom_request_ip` 5 в час на адрес, `showroom_request_tenant` 50 в сутки — 429 `003`;
  скрытое поле-ловушка (`website`) заполнено — 200 без записи и без заявки (боты).

### 2.5. Настройки — конфиг тенанта (P-11, NG-7)

```python
class ShowroomConfig(BaseModel):
    enabled: bool = False              # витрина в кабинете (сцена нужна отдельно)
    public_enabled: bool = False       # /showroom/{slug} без входа — только после письменного «да» отеля
    category_key: str                  # служба продаж — обязана быть категорией отеля (как у ресторана, spec 0064)
    assistant_enabled: bool = True     # False — только правила и кнопки, модели нет
    contact_note: LocalizedText | None = None   # «Отдел продаж отвечает в рабочие часы…» под формой
```

Поле аддитивное, переносится в `build_config` (иначе онбординг его сотрёт). Деплоймент:
`LLM_MODEL_SHOWROOM`, `LLM_SHOWROOM_DAILY_BUDGET_USD` — `.env.example`, compose (app и worker), README
шлюза (ADR-024, «Последствия»). У пилота служба продаж — новая категория `sales` в профиле `*.local`
(онбординг существующие категории не трогает, рунбук tenant-onboarding).

### 2.6. ПД агентов и юрдокументы (тем же PR, что миграция — правило 9 плана)

Агент — не гость, политика гостевого чата к нему не относится (она про чат и проживание). Поэтому
отдельная короткая страница `GET /legal/showroom-privacy` из `docs/legal/showroom-privacy.md`
(kk/ru/en: кто обрабатывает, какие данные — контакты и пожелания из формы, зачем — ответ на запрос,
срок — §3, кому передаются — тот же перечень субоператоров, что у гостя, кроме мессенджеров; права,
контакт privacy@necturn.com) и строка согласия на форме (§5) с версией `SHOWROOM_CONSENT_VERSION`
(`channels/showroom/consent.py`, дрейф с файлом ловит `tests/test_legal.py`); версия и время — в строке
запроса. Фразы помощника уходят в Anthropic (США) — политика просит не писать в помощник личные
данные, и они не хранятся. Строки [PII_REGISTRY](../PII_REGISTRY.md), раздел «Агенты» в
`docs/runbooks/subject-requests.md`, абзац [pilot-copy.md](../runbooks/pilot-copy.md) по образцу
«Квоты бесплатного» (в конфиге копии `showroom` нет; включение — письмо отелю по п. 1.2/1.3 договора).

## 3. Данные (PR 3 и PR 5, номера миграций — `ops/pool.sh reserve migration`)

- `showroom_scenes` (PR 3), тенантная, RLS по канону `0002`: `tenant_id` UNIQUE, `scene` JSONB
  (`SceneDocument`), `scene_version`, `replaced_by_user_id` (FK `users` ON DELETE SET NULL),
  `replaced_at`. ПД нет.
- `showroom_group_requests` (PR 5), тенантная, RLS, FK между модулями нет: `request_id` UNIQUE,
  `client_key` (UNIQUE `tenant_id, client_key`), `company`, `contact_name`, `phone`, `email`,
  `group_size` (CHECK 1–500), `check_in`, `check_out` (CHECK ≥ `check_in`), `room_numbers` JSONB,
  `wishes`, `language`, `consent_version`, `consent_at`, `created_at`, `anonymized_at`.
  **Срок:** контакты, компания и пожелания обезличиваются через **365 дней** с `created_at`
  (воркер ретеншна spec 0032 — своя ветка): сделка по группе живёт месяцами, 90 дней гостя — мало;
  число — решение окна, в founder-review. Удаление по обращению — рунбук subject-requests.

## 4. Контракты

- `showroom.api`: `get_scene() -> SceneRead | None`; `replace_scene(document, *, acting_user) ->
  SceneRead`; `find_rooms(RoomQuery) -> list[RoomMatch]` (номер, этаж, сторона, тип, виды; порядок —
  этаж сверху вниз, затем номер); `create_group_request(GroupRequestCreate, *, consent_version) ->
  GroupRequestRead`; `group_requests_for_requests(request_ids) -> dict[uuid, StaffGroupRequestRead]`;
  `anonymize_expired(now)`.
- Публичные (`channels/showroom`, контекст тенанта — сам по slug, как `channels/web`): `GET
  /showroom/{slug}` страница; `GET …/scene` сцена для просмотрщика; `POST …/navigate`; `POST
  …/requests` (201 новый, 200 повтор ключа; 422 `004`, 429 `003`); статика `GET /showroom/static/…`.
  Выключено или сцены нет — 404 `001` раньше всего остального.
- Кабинет: `GET /staff/{slug}/showroom` (менеджер, служба продаж; остальным — 403); `POST
  …/showroom/scene` multipart JSON — только менеджер, 422 `002` с путём ошибки; `POST …/showroom/navigate`.
  JSON без `Origin` — `ERR-AUTH-009`.
- Коды (статьи в `errors.md` — тем же PR, что код): `ERR-SHOWROOM-001` 404 витрина выключена или
  сцены нет; `-002` 422 сцена не прошла схему; `-003` 429 лимит навигации или запросов; `-004` 422
  запрос вне правил (даты, размер группы, номер не из сцены, поле длиннее предела).
- Метрики `showroom_navigations_total{source}`, `showroom_group_requests_total`; логи `showroom_*` с
  `tenant_id`, без контактов и без фраз агента.

## 5. Тексты (ru; en и kk — в теле PR 5, до кода)

**Страница.** Заголовок «3D-витрина отеля {название}». Под моделью: «Это схема здания, а не
фотография: этажи, стороны и виды — по данным отеля. Наличие номеров и цены уточняет отдел продаж.»
Кнопки видов «Горы · Город · Сверху · С улицы», линейка этажей, поиск номера. Поле помощника —
«Например: высокий этаж с видом на горы, двенадцать номеров рядом»; помощник выключен или бюджет
исчерпан — «Помощник отдыхает — пользуйтесь кнопками этажей и видов.» Панель подбора: «Этаж от … до …»,
«Сторона», «Тип номера», «Сколько номеров» — то же, что умеет помощник.

**Форма.** «Запрос в отдел продаж»; поля «Компания», «Контактное лицо», «Телефон», «Почта»,
«Гостей», «Заезд», «Выезд», «Выбранные номера» (с модели, можно убрать), «Пожелания» — «Этажи рядом,
завтраки, трансфер…». Строка согласия: «Отправляя запрос, я соглашаюсь на обработку указанных
контактных данных отелем и платформой для ответа на этот запрос — [политика конфиденциальности
витрины].» Под кнопкой «Отправить запрос»: «Это запрос, а не бронь: отдел продаж свяжется с вами,
уточнит наличие и условия.» После отправки: «Запрос отправлен. Отдел продаж отеля ответит вам по
телефону или почте.» Ошибка лимита: «Слишком много запросов с вашего адреса — попробуйте позже или
напишите отелю напрямую.»

**Помощник** (текст порождает модель — показываем промпт и образец). Промпт `showroom_navigate_v1`,
суть: «Ты ведёшь камеру по 3D-схеме отеля для агента, который подбирает номера для группы. Отвечай
только вызовом инструмента. Команды — из сводки сцены ниже; этаж или номер, которых в ней нет, не
называй. В reply — одно-два коротких предложения на языке агента: что показал и что можно уточнить.
Никогда не называй цены, наличие, скидки и не обещай номера — это делает отдел продаж.» Образец:
«высокий этаж с видом на горы, 12 номеров рядом» → `FindRooms(floor_from=19, side="east", count=12)`,
`SetView("mountains")`, reply «Показал 12 номеров на 19–20 этажах с горной стороны. Нужен один этаж
или подойдут два соседних?».

**Кабинет.** Карточка «🏢 Групповой запрос #12 · {компания} · {N} гост. · {заезд}–{выезд}»; строки
«Контакт: {имя}, {телефон}, {почта}», «Номера: 1901, 1903, …», «Пожелания: …»; под кнопками:
«Ответьте агенту по телефону или почте. «Готово» — когда ответили. Бронь — в Opera, как обычно.»
Уведомление браузера — «Групповой запрос #12». Пункт меню «3D-витрина»; кнопка «Загрузить сцену
(JSON)», «Сцена обновлена: версия {n}, {дата}»; отказ — «Сцена не принята: {путь} — {причина}».

## 7. Тесты

1. Сцена: лишнее поле, дубль номера, номер на этаже вне `floors_total`, `type_key` не из словаря,
   `sellable` у офисного этажа, > 512 КБ — `002` с путём; версия растёт; изоляция тенантов.
2. `find_rooms`: этажи, сторона, вид, тип, `count`; порядок; пустой результат — пустой список.

   модель выключена (ERR-AI-006) и бюджет исчерпан (ERR-AI-002) — `fallback` с текстом, не 5xx; команда
   с номером вне сцены отброшена; `reply` с валютой заменён; `forced_tool` стоит в запросе шлюза.
4. Лимиты: IP и тенант — `003`; fail-open по канону 0023.
5. Запрос: повтор `client_key` — та же заявка; `004` на датах, размере, чужом номере; ловушка — 200 без
   строк; заявка в `category_key` с `origin = showroom_form`, в `details` нет контактов; карточка берёт
   контакты из модуля; доля spec 0035 §4 запрос не считает; обезличивание через 365 дней; согласие
   записано с версией; `category_key` не из категорий отеля — ошибка конфига; онбординг поле не стирает.
6. Страницы: `public_enabled = false` или без сцены — 404 и нет пункта меню; кабинет — 403 чужой службе;
   CSP и отсутствие внешних загрузок (как `tests/test_site.py`); страница без cookies.
7. **Evals** `python -m hospitality.ai.evals.showroom_navigate [--repeat N]` — 36 фраз en/ru/kk/zh
   (агенты, не демография гостей) на вымышленной сцене: ожидаемые виды команд, язык `reply`, ни одной
