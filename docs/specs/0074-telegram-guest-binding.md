# Spec 0074: Telegram до подключения к копии — гость по коду заселения, персонал в границе службы

- **Статус:** принята (PR #912); код — тем же PR.
- **Issue:** #484 (находки К-2, К-3, О-1, О-2 [аудита безопасности 26.10](../audits/2026-10-26-security-audit.md)).
- **Дата:** 2026-11-10
- **Меняет:** [ADR-008](../adr/ADR-008-identity-and-access.md) §4 Q7 — Telegram переходит на
  auth-only (условие «после выдачи кодов в кабинете» наступило); [spec 0026](0026-staff-notification-routing.md)
  «Что сознательно НЕ делаем», первый пункт — исключение снято; [spec 0034](0034-emergency-intercept-and-urgent-requests.md)
  §4 — довод «гость не аноним, он в номере» теперь верен и для Telegram (§3 ниже).
- **Тексты гостю** — основателю до кода (файлом через диспетчера), решения окна —
  [founder-review](../founder-review/2026-11-10-pr912-telegram-binding.md).

## 1. Проблема

Telegram-гость не привязан к Stay: ход идёт без `verified_room_number`, лимиты — по `chat_id`.
Отсюда три дыры, которые откроются в день подключения бота к копии отеля:
- **деньги:** доля чата в дневном бюджете ($1 на аккаунт при потолке $10) — десять аккаунтов
  после одной кнопки согласия отключают консьержа всем гостям до полуночи UTC;
- **комната из текста** (H4 аудита 21.07): «почините сейф в 402» без Stay — заявка в 402, а
  срочная — без подтверждения гостя (ADR-018);
- **ЧП без лимита:** перехват стоит до лимитов, любой аккаунт — генератор срочных карточек,
  строк outbox и сообщений в чат службы.

И со стороны персонала: команды Telegram-чатов служб не знают границы службы — из чата уборки
`/done 1` закрывает заявку инженерии, гость получает «выполнена» без выполнения.

## 2. Гость: привязка кодом заселения

Тот же код, что в веб-чате (ADR-008 §3: «код работает в любом канале»), — тройкой
тенант + комната + код, тем же доменным путём `guests.start_guest_session`.

- **Идентичность.** `GuestIdentity(kind=telegram, external_id=chat_id)`; привязка — обычная
  `GuestSession` этого Stay (токен рождается и не выдаётся — Telegram опознаёт гостя по чату,
  не по cookie). Выезд гасит сессии Stay — гость снова не привязан (Q8), перевыпуск кода
  привязку не трогает (как у веба).
- **Привязан ли чат** — `guests.resolve_identity_session(kind, external_id)`: самая свежая
  живая сессия идентичности (не отозвана, Stay `checked_in`, срок не вышел), на каждом сообщении.
- **Привязанный гость** — общий ход (`run_guest_turn`) как в вебе: `verified_room_number` и
  `verified_stay_id` из Stay, ключ лимитов — `stay_id` (веб и Telegram одного Stay делят
  лимиты и денежную ступень).
- **Непривязанный гость** — строгий auth-only, без единого вызова модели и без заявок:
  1. ЧП-маркер (`urgency.detect_emergency`) — утверждённый текст ЧП («позвоните на ресепшен»,
     spec 0034 §3) без эскалации: текст ничего не обещает, а тревогу персоналу шлёт только
     привязанный гость;
  2. лимит сообщений чата (spec 0023, ключ `chat_id`) — как до согласия;
  3. сообщение вида «<комната> <код>» — попытка привязки (§2.1);
  4. иначе — подсказка «пришлите номер комнаты и код» + телефон ресепшена из конфига.
- **`/start` и приветствие после согласия** — непривязанному гостю к приветствию
  дописывается та же подсказка.

### 2.1. Попытка привязки

- **Разбор.** Код — шесть цифр в конце сообщения (`482913`, `482-913`, `482 913`), комната —
  последнее слово с цифрой перед ним (`305 482-913`, `комната 305, код 482-913`). Иначе — не
  попытка.
- **Лимиты** (до bcrypt, тратятся каждой попыткой, канон spec 0027 §3.3): по чату — scope
  `guest_code_verify_telegram`, и по комнате — **тот же** scope `guest_code_verify` и ключ
  `tenant:room`, что у веба: подбор кода с двух каналов сразу попыток не удваивает. Пределы и
  окно — `GUEST_CODE_VERIFY_RATE_LIMIT_*`. Отказ — лог-код `ERR-TELEGRAM-009`, метрика
  `guest_rate_limited_total` (алерт ERR-OPS-014 видит новую дверь).
- **Код не хранится.** Входящее непривязанного гостя, разобранное как попытка, пишется в
  `messages` как «<комната> [код заселения]»: в «Диалогах» видно, что гость входил, кода — нет.
  Идемпотентность (P-8) — по-прежнему ключ входящего.
- **Ответы** — «Готово, номер N подключён…», «Код не подошёл…», «Слишком много попыток…»
  (два последних — те же фразы, что в вебе). Язык — по языку клиента Telegram, неизвестен —
  три подряд (канон приветствия).

## 3. ЧП-перехват — только для привязанного гостя

Перехват с эскалацией (spec 0034 §4) остаётся первым шагом общего хода — но до общего хода
теперь доходит только привязанный гость. Довод spec 0034 «гость не аноним, он в номере» снова
верен для обоих каналов. Непривязанный получает тот же текст ЧП без тревоги персоналу (§2).

## 4. Персонал: граница службы для Telegram-чатов

Обратное правило «чат → службы» из `TenantConfig.staff_chats_by_category`:
- **все службы** (`allowed_category_ids=None`, как ресепшен и менеджер в RBAC) — дефолтный чат
  инсталляции (`TELEGRAM_STAFF_CHAT_ID`, туда же идёт всё неразмеченное), чат утренней сводки
  (группа руководства) и чат, на который размечена служба ресепшена;
- **чат службы** — только категории, ключи которых размечены на этот чат;
- конфиг не прочитался — чат службы не может ничего (fail-closed; дефолтный чат — может).

Граница стоит в тех же местах, что в кабинете: переход (`change_request_status(...,
allowed_category_ids=…)` — ERR-REQUESTS-007 под блокировкой строки), поиск `#N` (чужие службы
не видны — `/done 1` из чата уборки находит #1 уборки), кнопки «Отменить» и «Готово частично»
(тост «Заявка другой службы» вместо списка причин). Актора у команд Telegram по-прежнему нет —
«кто сделал» в логе (`actor_external_id`).

## 5. Что сознательно не делаем

- Deep-link `t.me/bot?start=<токен листка>` — QR листка ведёт в веб-чат; второй QR не печатаем.
- Привязку группового чата не различаем: гостевой чат приватный, группа с ботом, не размеченная
  персоналом, — тот же «гость».
- Флага «auth-only выкл.» нет: открытый бот — ровно то, что закрывает спека.
- Комната привязанного Telegram-диалога в «Диалогах» кабинета — `conversations.guest_identity_id`
  у Telegram не заполняется (запись в `docs/later/`).

## 6. Тесты

- Непривязанный: «почините сейф в 402» — модель не вызвана, заявки нет, ответ — подсказка;
  ЧП — текст ЧП без эскалации; код верный — привязка, следующий ход идёт с комнатой Stay и
  ключом `stay_id`; неверный — отказ; лимит — отказ без bcrypt; после выезда — подсказка;
  код в `messages` не записан.
- `resolve_identity_session`: свежая сессия, отозванная, выезд, чужая идентичность.
- Персонал: `/done 1` из чата другой службы — отказ, заявка не изменилась; поиск `#N` видит
  только свою службу; кнопка с чужим UUID — тост-отказ; дефолтный чат и чат сводки — любые.
- Smoke (spec 0019) проходит гостем, привязанным кодом: заселение в начале прогона, выезд в конце.
