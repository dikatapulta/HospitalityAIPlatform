# Spec 0075: антивирус для файлов гостя — ClamAV при приёме PDF и DOCX

- **Статус:** реализуется (PR #913)
- **Issue:** #502 — нашло ревью PR #500; место в разделе 1 — решение основателя 10.11 в issue.
- **Дата:** 2026-11-10
- **Меняет:** [ADR-022](../adr/ADR-022-file-storage.md) — антивирус больше не отложен (там же
  дополнение); [spec 0047](0047-file-storage.md) §4 и §7 — шаг проверки и коды 007, 008.

## 1. Проблема

FOUNDATION §11 требует антивирус для загрузок; ADR-022 отложил его до прод-контура в РК и сам
назвал условие пересмотра: персонал регулярно открывает документы гостей на компьютерах отеля.
Это и есть реквизиты для АВР ([spec 0049](0049-act-requisites.md)): бухгалтер скачивает PDF и
DOCX гостя и открывает их у себя. Узел файлов отвергает только DOCX с макросами; PDF со
скриптом, DOCX с OLE-объектом или ActiveX проходят как есть.

## 2. Решения

**Р-1. ClamAV рядом со стеком.** Контейнер `clamav` (clamd и freshclam, образ
`clamav/clamav:1.5_base-debian`; базы — в томе `clamav_data`, freshclam обновляет их сам). Файл
идёт ему по сети compose протоколом clamd `INSTREAM` и с сервера не уходит. Внешний сервис
проверки отвергнут: файл гостя покинул бы контур — против ст. 12 закона о ПД и ADR-006. Новой
Python-зависимости нет: протокол — десяток строк на asyncio.

**Р-2. Проверяется то, что хранится как прислано: PDF и DOCX.** Картинку узел перекодирует в
WebP (spec 0047 §4), присланные байты выбрасываются — проверять нечего. Сегодня PDF и DOCX
принимает одно назначение, `guest_document`; новое назначение с документами получит проверку
само.

**Р-3. При приёме, а не в воркере.** `store_upload`: песочница → антивирус → шифрование →
хранилище. Гость узнаёт об отказе сразу, на той же форме, и персонал не видит файла, который
не проверен. Отвергнуто: проверка в воркере до показа персоналу — новое состояние файла «на
проверке», миграция и экран, а гость узнал бы об отказе позже и в чате. Цена — до секунды на
файл до 10 МБ на пути отправки формы. Разбирает файл clamd в своём контейнере, веб-процесс
только пересылает байты (изоляция §11).

**Р-4. Нашёл — отказ, без карантина.** ERR-FILES-007 (422): файл не сохраняется, гость видит
текст §5 и может прислать фото — его узел перерисует. Карантин отвергнут: хранить вредонос
ради бухгалтера, которому его всё равно нельзя открыть, — риск без пользы. Лог `file_infected`
(WARNING) с именем сигнатуры — оно не ПД; имя файла в лог не идёт (spec 0047 §7).

**Р-5. Антивирус не ответил — файл не принят (fail-closed).** Нет контейнера, отказ соединения,
таймаут 30 с, ответ clamd `ERROR` — ERR-FILES-008 (503), гостю — «попробуйте через минуту».
Принять без проверки нельзя: смысл узла — непроверенный файл до бухгалтерии не доходит.

**Р-6. Где работает.** Порт `VirusScanPort` с двумя адаптерами (ADR-007), выбор —
`VIRUS_SCAN_BACKEND`:
- `fake` — умолчание кода: dev, CI, тесты. Находит тестовую строку EICAR, остальное чисто;
- `clamav` — умолчание compose-файла контуров (`docker-compose.staging.yml`): контур, где
  включат документы гостя, без антивируса файл не примет (Р-5), а не примет непроверенный.

Контейнер `clamav` — под профилем compose `antivirus` (`COMPOSE_PROFILES=antivirus` в `.env`):
по документации ClamAV он держит 1,2 ГБ памяти и до 2,4 ГБ при ежедневной перезагрузке баз, а
нужен только контуру с `ENABLE_GUEST_DOCUMENTS=true`. Контуры:

| Контур | Документы гостя | Антивирус |
|---|---|---|
| Живой отель (сейчас — гостевая копия) | выключены до переезда в РК (spec 0049 Р-7) | при включении — профиль `antivirus` |
| Staging | включены, данные выдуманные | `VIRUS_SCAN_BACKEND=fake` в `.env`: сервер общий с копией, 2,4 ГБ лишние |
| Локальный `ops/docker-compose.yml` | по желанию | `fake`; настоящий — `--profile antivirus` и `VIRUS_SCAN_BACKEND=clamav` |

Прод-контур в РК с документами гостя — 6 ГБ памяти вместо 4
([founder-actions-pilot-launch.md](../runbooks/founder-actions-pilot-launch.md), таблица сервера).

## 3. Контракты

**Порт** `shared/ports/virus_scan.py`: `scan(data) -> ScanResult` (`infected: bool`,
`signature: str | None`), `check() -> bool` (clamd отвечает на `PING`); не ответил —
`VirusScanUnavailableError`. Композиционный корень (`app.py`) кладёт адаптер
`set_virus_scanner`, `store_upload` берёт `get_virus_scanner()`. Воркер файлов не принимает и
адаптера не держит.

**Адаптеры** `integrations/virus_scan/`: `FakeVirusScanAdapter`, `ClamdVirusScanAdapter(host,
port)` — `zINSTREAM`, куски по 64 КБ, ответ `stream: OK` / `stream: <сигнатура> FOUND` /
`… ERROR`. Настройки: `VIRUS_SCAN_BACKEND`, `CLAMAV_HOST` (умолчание `clamav`), `CLAMAV_PORT`
(`3310`).

**Коды** ([errors.md](../runbooks/errors.md)): ERR-FILES-007 — 422, файл не прошёл антивирус;
ERR-FILES-008 — 503, антивирус не ответил. Метрика `file_operations_total`: `rejected/infected`
и `error/antivirus`.

## 4. Наблюдаемость

`file_infected` (сигнатура, назначение, размер) и `file_antivirus_failed` (ERR-FILES-008,
причина) — WARNING, не ERROR: ERROR унёс бы файл в Sentry (#433). `/health/ready` антивирус не
проверяет: на staging документы включены без него, и красный ready ронял бы деплой. Алерт на
ERR-FILES-008 — до включения документов у живых гостей ([docs/later](../later/)).

## 5. Тексты

Гостю на форме реквизитов (ERR-FILES-007), под файлом — выбраны основателем 10.11, вариант А
([founder-review](../founder-review/2026-11-10-pr913-antivirus-text.md)):
- ru: «Файл {name} не прошёл проверку на вирусы. Пришлите фото документа или другой файл.»
- kk: «{name} файлы вирусқа тексеруден өтпеді. Құжаттың фотосын немесе басқа файл жіберіңіз.»
- en: «{name} didn't pass the virus check. Please send a photo of the document or another file.»

ERR-FILES-008 — общий «Не получилось отправить. Попробуйте ещё раз через минуту.».

## 6. Тесты

- Контракт порта на обоих адаптерах (`tests/test_virus_scan_port.py`): чистый файл, EICAR,
  пустой файл, `check`; clamd — на тестовом сервере протокола в том же процессе: куски и
  нулевой конец, `FOUND`, `ERROR`, обрыв, таймаут, нет соединения.
- Узел (`tests/test_files.py`): PDF с EICAR — 007, ни файла, ни строки; антивирус лежит —
  008; картинка до антивируса не доходит.
- Форма гостя: код 007 — свой текст, а не «попробуйте ещё раз».
- Настоящий clamd — руками при включении (рунбук), в CI его нет: 1,2 ГБ и загрузка баз.

## Не входит

Повторная проверка при скачивании свежими базами; алерт ERR-FILES-008; антивирус для
картинок; проверка файлов персонала — PDF и DOCX принимает только назначение гостя.
