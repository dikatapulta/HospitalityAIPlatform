# Spec 0080: вернуть выполненную заявку в работу

- **Статус:** принята (PR #995, спека и код одним PR).
- **Issue:** #55. Барьер и тексты решены по рекомендации окна — слово основателя 10.11 (#909), запись
  [founder-review](../founder-review/2026-11-11-pr995-reopen-done.md).
- **Дата:** 2026-11-11
- **Меняет:** жизненный цикл заявки (ADR-013, README `modules/requests`) — ребро `done → in_progress`;
  [spec 0065](0065-staff-stats.md) §2.2 — «Готово», которое вернули, не засчитывается.

## 1. Проблема

`done` необратим: «Готово», нажатое не на той заявке, исправляется только руками в базе. Гость получил
«Ваша заявка выполнена» — неправда от лица отеля, — а настоящая заявка выпала из работы: она закрыта,
её никто не ищет. В Telegram «✅ Готово» срабатывает с одного нажатия; в кабинете промах — не та
карточка. Отмена такой проблемы не имеет: у неё обязательная причина из списка (spec 0057) — второй шаг.

## 2. Решение — «Вернуть в работу»

Из трёх барьеров #55 выбран явный возврат с журналом: окно отмены в минуты не ловит жалобу гостя через
час, «Вы уверены?» на каждое «Готово» — лишнее нажатие на каждой заявке.

### 2.1. Домен (`modules/requests/reopen.py`)

`reopen_request(request_id, *, initiator=None, acting_user=None, allowed_category_ids=None)`:
`done → in_progress` под блокировкой строки, одной транзакцией:

- снимаются `closed_at`, `closed_by_*`, `resolution_note` — заявка снова открыта, следующее «Готово»
  пишет своё (иначе старое примечание сделало бы новое «выполнена» «частичным»);
- пара взятия остаётся — заявка возвращается тому, кто её делал; ушёл со смены — «Вернуть в очередь»;
- `reopen_count += 1` (миграция `0074`) — по нему уведомитель гостя различает закрытия (§4);
- событие `request.status_changed` (`done → in_progress`); с `acting_user` — строка журнала
  `request_reopened` «Возвращена в работу».

Ребро объявлено в `service.py` рядом с картой — `REOPEN_TRANSITION`, — но не в `STATUS_TRANSITIONS`:
общий `change_request_status` закрытую не воскрешает, устаревшая кнопка «Взять» по-прежнему получает
`ERR-REQUESTS-003`. Карта и ребро — единственное место, где объявлены переходы (P-5).

### 2.2. Срок — сутки

`REOPEN_WINDOW = 24 ч` от `closed_at`: промах замечают сразу или по жалобе гостя в тот же день; позже —
новая просьба и новая заявка. Константа домена, не настройка тенанта: отелю выбирать здесь нечего.
`closed_at` пуст (закрыта до spec 0035) — срок не посчитать, возврата нет.

### 2.3. Что не возвращается

`origin` `guest_form` (заказ в номер, бронь столика, запрос АВР) и `showroom_form` (витрина): их шаги
гостю шлют свои подписчики с ключом на шаг — поправки у них нет, а второе «Доставлено» ключ бы погасил.
Возврат оставил бы гостю «доставлено» без еды. Отказ — `ERR-REQUESTS-009`; задача — #998. Отменённая
не возвращается — у отмены уже есть второй шаг (причина).

### 2.4. Итоги по сотруднику

«Готово», за которым в журнале идёт «Возвращена в работу», в «Статистике» (spec 0065) не считается
выполненной заявкой: закрытие было ошибкой. Следующее «Готово» той же заявки — считается.

Остаток, заведённый закрытием (spec 0079), остаётся своей заявкой: лишний — отменить с причиной «Дубль».

## 3. Где кнопка

- **Кабинет:** «Вернуть в работу» в панели выполненной заявки (вкладки «Закрытые», «За 7 дней»), пока
  `can_reopen`; `POST …/api/requests/{id}/reopen`. Всплывашка после «Готово» — «Заявка #12 выполнена»
  и «Отменить» (7 с), если ответ несёт `can_reopen: true` (нет у заявки формы и при остатке);
  итог — «Заявка #12 снова в работе». Ошибка 009 — «Прошли сутки — эту заявку уже не вернуть.
  Заведите новую.»
- **Telegram:** под выполненной — «↩️ Вернуть в работу» (`req:<uuid>:reopen`), если `can_reopen`; итог —
  как у прочих кнопок, кнопки — снова «Готово / Готово частично / Отменить». Команды нет: номер `#N`
  ищется среди незакрытых.

Кто вправе — тот же, кто закрывает: сотрудник службы заявки (граница spec 0045 §5, `ERR-REQUESTS-007`).
Ни гостю, ни модели возврата нет.

## 4. Гость

- **Поправка** — подписчик `channels/telegram/reopen_notice.py` на `done → in_progress`, тем же путём,
  что итог (адрес по `request_origins`, канонический русский и один вызов перевода):
  «Простите, мы поторопились: заявка «{суть}» ещё не выполнена. Мы уже занимаемся ею.» Только если
  «выполнена» этого закрытия ушло; ключ — `guest:request_reopened:<id>:<reopen_count>`; без
  `messages.request_id` — кнопок оценки под поправкой нет.
- **Опоздавшее «выполнена»:** вернули раньше, чем воркер доставил итог, — уведомитель итога видит, что
  заявка уже не `done`, и молчит; поправлять тогда нечего.
- **Следующее «выполнена»:** ключ итога `done` — с суффиксом номера возврата
  (`guest:request_done:<id>:<n>`, у первого закрытия — прежний, без суффикса).

Заявки из чата гостя у пилотного отеля выключены (#384) — поправку гость увидит, когда их включат.
