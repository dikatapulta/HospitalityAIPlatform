# Spec 0082: отметка согласия сотрудника на ИИ-разделы кабинета

- **Статус:** принята (PR #1003, спека и код одним PR).
- **Issue:** #985 — находка юрпакета #948 (PR #984).
- **Дата:** 2026-11-11
- **Меняет:** [spec 0048](0048-mentor.md) §6, [spec 0071](0071-staff-ideas.md) §8 — раздел открыт не
  всем уровням, а тем, у кого есть отметка; [spec 0072](0072-mentor-exam-rollout.md) §3 — сотрудник без
  отметки не в «Итогах экзаменов»; [spec 0077](0077-staff-memos.md) §7 — кнопка «Оформить» только
  с отметкой.

## 1. Проблема

Основание передачи данных работника в США — его письменное согласие, отдельно на каждого получателя:
пункт 2 бланка — «Наставник» и OpenAI, пункт 3 — «Предложить идею», кнопка «Оформить» и Anthropic
([staff-notice.md](../legal/staff-notice.md); Закон № 94-V, ст. 7 п. 6 и ст. 16 п. 3 пп. 1 в редакции
14.09.2026). Кабинет о согласии не знал: раздел включался на весь отель, и работник, который галочку
не поставил или согласие отозвал, видел «Наставника» и мог задать вопрос — текст уходил в OpenAI без
основания. Держала это только обязанность отеля «не поручать пользоваться разделом» (допсоглашение
п. 3.2) — на сотни работников с 01.12 организационной меры мало.

## 2. Решение

### 2.1. Данные

Отметка живёт на членстве в отеле — согласие дают отелю, и в другом отеле его нет:
`tenant_memberships.ai_consents` — массив получателей `AiRecipient` (`openai`, `anthropic`),
`VARCHAR(16)[] NOT NULL DEFAULT '{}'` (миграция 0075). Умолчание — пусто: согласие не предполагается,
и выкат никого не включает — на копии отеля «Наставник» живым сотрудникам ещё не открыт. Умолчание
в БД остаётся навсегда: старый образ при откате вставляет членства без этой колонки.

Отметка — по получателю, как пункты бланка, а раздел знает своего получателя (одна таблица в коде,
`staff_portal/ai_consent.py`):

| Раздел | Получатель |
|---|---|
| «Наставник» — все вкладки, «Неточность в статье», назначенный экзамен | `openai` |
| «Предложить идею» — все вкладки | `anthropic` |
| «Оформить» в служебной записке (spec 0077, PR 6) | `anthropic` |

Получатель раздела задан текстом согласия, а не `LLM_MODEL_*`: перевод раздела к другому провайдеру —
новый бланк и сброс отметок этого получателя, то есть отдельная задача.

### 2.2. Кто ставит

Менеджер в «Сотрудниках» — галочкой у строки, в том числе у своей: отметка — не право, а факт бумаги,
самоблокировки она не даёт. Строка суперадмина отметок не имеет (ERR-AUTH-013, spec 0044 §2), и
проверка его не держит: суперадмин — сам оператор, не работник отеля. Галочки видны у получателя,
чей раздел включён у отеля: `openai` — при `mentor_enabled`, `anthropic` — при `ideas_enabled` или
`memos_enabled`.

Действие — `POST /staff/{slug}/api/team/members/{user_id}/ai-consent`, тело `{"recipients": [...]}` — полный
набор отметок строки (идемпотентно). Права и границы — как у смены уровня (`staff_team`): только
менеджер, только активное членство этого отеля (иначе 404 ERR-AUTH-008), суперадмин — 409
ERR-AUTH-013; CSRF-щит JSON-действий. Лог `staff.member_ai_consents_changed`: кто, кому, было и стало.

### 2.3. Где действует

`StaffContext.ai_consents` читается с членством на каждом запросе — снятая отметка закрывает раздел
следующим же запросом. Проверка — одна, в `require_section` раздела, через который идут его страницы и
действия:

- пункта меню и плитки на главной нет;
- страница раздела — 403 «Раздел закрыт» с объяснением (§3);
- JSON-действия — 403 ERR-AUTH-003, лог `staff.ai_consent_missing` с получателем; в модель ничего
  не уходит — вызов шлюза стоит после проверки;
- «Итоги экзаменов» не считают сотрудника без отметки `openai`: экзамен ему не виден, «не проходили»
  был бы неправдой; над карточками — сколько таких;
- «Оформить» (PR 6 spec 0077) — кнопки нет без отметки `anthropic`: `ai_consent.has(staff, recipient)`.

Раздел, выключенный у отеля, по-прежнему отвечает 404: сначала флаг отеля, потом отметка.

### 2.4. Снятие

Работник отозвал согласие — менеджер снимает отметку, раздел закрывается сразу. Данные снятие не
удаляет: удаляет оператор по письменному указанию отеля — [subject-requests-staff.md](../runbooks/subject-requests-staff.md)
§5, по блоку на получателя.

## 4. Не входит

- Электронное согласие в кабинете — бумага остаётся (допсоглашение п. 3.1).
- Отметка при приглашении, в том числе списком, —
  [later](../later/2026-11-11-pr1003-consent-at-invite.md).
- Удаление данных при снятии отметки — руками по рунбуку (§2.4).

## 5. Тесты

- Миграция: колонка с умолчанием `{}`, откат на 0073.
- `ai_consent`: без отметки раздел закрыт (меню, страница 403, ход «Наставника» и «Предложить идею»
  403 без вызова модели, флаг статьи, старт экзамена); с отметкой — открыт; суперадмин — без отметки;
  выключенный раздел — 404 и без отметки.
- «Сотрудники»: отметка сохраняется и снимается, себе — можно, суперадмину — 409, чужой отель — 404,
  не менеджер — 403, неизвестный получатель — 422; галочки видны только при включённом разделе.
- «Итоги экзаменов»: сотрудник без отметки не в карточке, строка-счётчик.
