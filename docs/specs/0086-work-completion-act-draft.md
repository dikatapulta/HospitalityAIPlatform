# Spec 0086: черновик АВР по кнопке бухгалтера — форма Р-1, Excel и PDF (черновик Phase 3)

- **Статус:** реализуется — PR 1 (#1022): спека, данные, домен, порт и Excel; PR 2 — кабинет;
  PR 3 — PDF
- **Issue:** #953 — слово основателя 10.11.2026: «можешь задачи с фаз 3-4 брать … пусть как-то
  основу делают в качестве черновика»
- **Дата:** 2026-11-11
- **Опирается на:** [spec 0049](0049-act-requisites.md) (строки, «Проверено», права Р-10),
  [spec 0052](0052-act-requisites-1c-export.md) (порт `AccountingPort`), [spec 0032](0032-guest-text-retention.md) (срок)

## 1. Проблема

Бухгалтер получает реквизиты гостя строкой таблицы (spec 0049) и файлом для 1С (spec 0052), а
сам акт набирает руками. План ставит выпуск АВР в Phase 3; основатель перенёс его черновиком
(план, Phase 1, «Перенесено»). Автоматического выпуска нет и не будет (NG-4, P-9): акт
появляется только по кнопке бухгалтера и только из реквизитов, которые он подтвердил.

## 2. Решения

**Р-1. Форма — Р-1 «Акт выполненных работ (оказанных услуг)».** Приложение 50 к приказу
Министра финансов РК от 20.12.2012 № 562 «Об утверждении форм первичных учетных документов»,
в редакции приказа № 458 от 27.10.2014; приказ — с изменениями на 28.03.2018, позже Приложение
50 не менялось (zakon.uchet.kz/rus/docs/V1200008265, сверено 11.11.2026). Основание —
Закон РК «О бухгалтерском учете и финансовой отчетности» № 234-III, ст. 7 п. 2: формы первичных
документов утверждает уполномоченный орган (редакция 21.10.2026, zakon.uchet.kz/rus/docs/Z070000234_).
Черновик повторяет поля формы: ИИН/БИН и «полное наименование, адрес, данные о средствах
связи» заказчика и исполнителя; «Договор (контракт) № … от …»; номер документа и дата
составления; таблица из восьми граф (номер по порядку, наименование услуг, дата оказания,
сведения об отчёте, единица, количество, цена за единицу, стоимость) и «Итого»; «Сведения об
использовании запасов», «Приложение», «Сдал (Исполнитель)» и «Принял (Заказчик)» с должностью,
подписью и расшифровкой, «М.П.», дата подписания и три сноски формы. Подпись, печать и дату
подписания ставят люди на бумаге — платформа их не заполняет. Язык — русский; казахский
вариант формы — `docs/later/`. Решение — [founder-review](../founder-review/2026-11-11-pr1022-act-form.md).

**Р-2. Только подтверждённые реквизиты, только по кнопке.** Акт формируется для строки
«Проверено» (spec 0049 Р-5), не обезличенной и не возвращённой гостю (заявка не `cancelled`);
иначе — ERR-DOCUMENTS-007. Подписчика, джобы и инструмента ИИ, создающих акт, нет. В акт ложится
**снимок**: все шесть полей строки, кто и когда нажал «Проверено», исполнитель (Р-4), номер,
дата, договор, строки и суммы. Это и есть «версия» подтверждённого набора: правка поля снимает
«Проверено», как и раньше, новый акт требует новой проверки, а прежний акт хранит свой снимок.
Отдельной истории реквизитов нет — правки и проверки и так в журнале изменений (spec 0041).

**Р-3. Услуги и суммы вводит бухгалтер.** Из PMS ничего не берётся. Номер акта — текст до 30
знаков (нумерация живёт в 1С отеля), дата составления, договор — текст до 100 знаков,
необязательно. Строк 1–20: услуга до 200 знаков, дата оказания — текст до 40 (графа 3 формы
заполняется, только когда даты разные), единица до 20, количество > 0 и ≤ 99 999 (до трёх
знаков после запятой), цена ≥ 0 и ≤ 9 999 999 999,99 ₸ (до двух). Стоимость = количество × цена,
округление до тиына half-up; «Итого» — сумма стоимостей, количество в «Итого» — только когда
у всех строк одна единица. Валюта — тенге. Графы 4 и «запасы» пусты: у гостиничных услуг
отчётов и давальческих материалов нет.

**Р-4. Исполнитель — конфиг тенанта `act_executor`** (§6): название, БИН/ИИН, адрес, контакты.
Пишет онбординг из файла профиля, повторный онбординг без ключа переносит прежнее (как
`room_service`). Не задан — ERR-DOCUMENTS-008: акт без исполнителя бухгалтеру бесполезен.

**Р-5. Хранение.** Таблица `work_completion_acts` (тенантная, RLS-канон 0002, миграция PR 1):
`act_request_id` (FK CASCADE), открытые `number`, `composed_on`, `total`, `created_by_user_id`
(FK `users` SET NULL), `created_by_display_name`, `created_at`, `anonymized_at`; снимок Р-2 —
`content_ciphertext` (JSON, AES-256-GCM ключом `FILE_ENCRYPTION_KEY`, AAD
`{tenant_id}/work_completion_acts/{id}/content_ciphertext`, `platform/field_encryption.py`).
Изменить акт нельзя — API правки нет; ошибка — новый акт. Файл не хранится: его собирает адаптер
из снимка при каждом скачивании, содержимое не меняется.

**Р-6. Срок — как у запроса.** Черновик несёт те же ПД (ИИН и ФИО ИП, адрес), что и запрос, и
обезличивается вместе с ним (spec 0032): `content_ciphertext` и имя сформировавшего — NULL,
строка живёт (номер, дата, сумма). Подписанный акт хранит отель в своём учёте (закон № 234-III
ст. 11) — черновик платформы его архивом не является.

**Р-7. Файлы — через порт.** `AccountingPort.render_act(act, *, file_format) -> ExportFile`:
Excel — тем же сборщиком без сторонних библиотек (`integrations/accounting/xlsx.py`), лист на
A4 альбомом по ширине: количество, цена и стоимость — числа (цена и стоимость — `#,##0.00`),
прочее — текст, «=…» остаётся строкой. PDF — PR 3: библиотека `fpdf2` (чистый Python,
встраивание TTF) и шрифт под OFL с казахскими буквами в репозитории. Fake отдаёт JSON того же
снимка. Имя файла — «АВР № 15 от 11.11.2026.xlsx»; `/` и прочие недопустимые в имени файла
знаки номера — дефис.

**Р-8. След.** Журнал изменений: `work_completion_act_created` «АВР сформирован», «Что» —
заявка запроса (`#12 · Бухгалтерия · 512`), без значений. Скачивание журнал не пишет — как
выгрузка для 1С (spec 0052 Р-6). Логи `work_completion_act_created` и
`work_completion_act_rendered` (id, число строк, формат, `user_id` — без значений), метрика
`work_completion_acts_total{tenant_id,event}` (`created`, `rendered`).

**Р-9. Права и выключатель.** Те же, что у страницы: `can_handle_act_requests` (spec 0049 Р-10).
Кабинет — за флагом контура `ENABLE_WORK_COMPLETION_ACTS` (умолчание `false`, PR 2); на staging
включает `STAGING_ALL_FEATURES`, на гостевой копии — по слову основателя после переезда в РК
(spec 0049 Р-7).

## 3. Контракты

**`documents.api`:** `create_work_completion_act(act_request_id, WorkCompletionActCreate, *,
acting_user) -> WorkCompletionActRead`; `list_work_completion_acts(act_request_ids) ->
dict[UUID, list[WorkCompletionActRead]]` — для строк страницы, новые сверху;
`render_work_completion_act(act_id, file_format, *, acting_user) -> ExportFile`.

**Порт:** `ActDocument` (номер, дата, договор, `customer`/`executor` — `ActParty`, строки
`ActLine` со стоимостью, `total`) и `ActFileFormat` (`xlsx`; `pdf` — PR 3).

**HTTP (PR 2):** `POST /staff/{slug}/api/act-requests/{id}/acts` (JSON, `Origin` — как у
правки); `GET /staff/{slug}/act-requests/acts/{act_id}.{xlsx|pdf}` — вложением, `no-store`.

**Коды** (статьи errors.md — PR 1): `ERR-DOCUMENTS-007` 409 — реквизиты не подтверждены
(нет «Проверено», запрос обезличен или возвращён гостю); `-008` 409 — у отеля не задан
исполнитель; акт не найден или обезличен — прежний `-004`; формат полей формы — 422 схемы.

## 4. Тексты кабинета (PR 2)

Показаны записью [founder-review](../founder-review/2026-11-11-pr1022-act-form.md) до кода.
Кнопка у строки «Проверено» — «Сформировать АВР»; у строки «Проверить» её нет. Форма:
«АВР для {контрагент} · № {номер}»; «Номер акта», «Дата составления», «Договор — необязательно,
например «№ 12 от 01.11.2026»»; строки — «Услуга», «Дата оказания — если не совпадает с датой
акта», «Ед.», «Кол-во», «Цена, ₸», «Стоимость», «+ Строка», «Убрать»; «Итого: 45 000,00 ₸»;
подсказка «Услуги и суммы вписываете вы — из PMS ничего не берётся. Реквизиты — проверенные:
изменить их можно в строке таблицы, после этого — «Проверено» и новый акт»; «Сформировать»,
«Отмена». Первая строка заполнена: «Проживание, номер {номер}, {заезд}–{выезд}», «сутки»,
количество — число ночей, цена пустая. Под строкой — «АВР № {n} от {дата} · {итого} ₸ ·
{кто}» и ссылки «PDF», «Excel». Отказы: 007 — «Реквизиты изменились после проверки — нажмите
«Проверено» и сформируйте акт заново»; 008 — «Реквизиты отеля для АВР не заданы — их вносит
администратор платформы».

## 5. Тесты

- Домен (`documents/tests/test_acts.py`): акт только у «Проверено» — «Проверить», правка после
  проверки, возврат гостю, обезличенный → 007; нет исполнителя → 008; снимок не меняется после
  правки строки; стоимость и «Итого» с округлением; шифртекст в БД и чужой AAD не расшифруется;
  изоляция тенантов (P-4); журнал без значений; обезличивание запроса обезличивает его акты.
- Порт (`tests/test_accounting_port.py`): оба адаптера — номер, стороны, строки и суммы в
  файле; Excel — числа числами, текст текстом, формул нет, байты воспроизводимы.
- Онбординг: `act_executor` из профиля, перенос без ключа.
- PR 2 — кабинет: служба без `accounting` — 403, JSON без `Origin` — ERR-AUTH-009, скачивание
  вложением; PR 3 — PDF: кириллица и казахские буквы извлекаются из файла текстом.

1. **Этот PR:** спека, строка плана, GLOSSARY; миграция, модели, `documents/acts.py`, порт,
