# channels/web — гостевой веб-чат по QR (spec 0027, issue #79)

## Назначение

Второй гостевой канал: гость сканирует статический QR в номере
(`https://<хост>/g/{tenant_slug}/{room}`), вводит код заселения с карточки
ресепшена (ADR-008 §3) и общается с тем же AI-консьержем, что в Telegram.
**Строгий auth-only с рождения** (Q7, решение 22.07): без валидной
`GuestSession` — статический ответ `ERR-WEB-002` без единого вызова LLM и без
заявок; после выезда — то же (Q8, валидность перепроверяется на каждом
действии). Транспорт — HTTP JSON + одна статическая страница; ход гостя —
общий `channels/common/guest_turn` (spec 0027 §2).

## Маршруты (`/g/{tenant_slug}/{room_number}` и `/w/{tenant_slug}/b/{token}`)

| Маршрут | Auth | Что делает |

| `GET /g/…/` | нет | HTML-страница чата (`page.py`, вид — #746): название отеля из `tenants.name` в шапке и на вкладке; экран входа — kk, ru, en (#224), после входа надписи на языке гостя; плашка «Заказать в номер» — только у отеля с включённым room service, «Забронировать столик» — только с включённой бронью (spec 0064); обе видны после входа; цвет подложки, узор и знак отеля — выбор отеля (spec 0066, `look.py`), читается при каждом открытии |

| `POST /g/…/messages` | сессия | `{text, client_message_id}` → общий ход гостя → `{replies, reply_ids}` синхронно; повтор `client_message_id` — `duplicate: true` (P-8): страница шлёт повтор недоставленного с прежним ключом, и дошедшее первый раз не становится вторым платным ходом (#117); ход, молча остановленный лимитом чата, — `pause` с текстом отказа: страница показывает его плашкой под строкой ввода, в историю он не пишется (#222); ход, упавший неожиданной ошибкой до реплики, — тоже 200 с репликой деградации, а не 500 с «не доставлено» (страховка хода, `channels/common`, #43) |
| `GET /g/…/messages?after=` | сессия | история/новые сообщения (poll раз в ~5 с; так доезжают подтверждения заявок от подписчика) и `room_number` сессии: адрес другой комнаты страница меняет на свой (spec 0068 §2.2). У входящего — `client_message_id` его отправки; у фото гостя — `photo_url` (адрес картинки), `text` пуст; фото выключены — их в ленте нет (spec 0081 §4). Страница рисует каждое сообщение один раз: своё — по `client_message_id`, реплики из ответа отправки — по `reply_ids`, а курсор `after` берёт только из опроса — прыжок курсора на реплику хода терял исходящее подписчика, записанное посреди хода (#117); `last_message_id` в ответе отправки — для страниц, открытых до этого |
| `POST /g/…/feedback` | сессия | Палец вверх или вниз под итогом выполненной заявки (spec 0076, `feedback/router.py`): `{request_id, rating}` → `{request_id, rating, commented, passed_to_staff}`; Stay — только из сессии; повтор той же оценки — прежний ответ без второй карточки, другая — 409 `ERR-FEEDBACK-003`; оценки выключены — 404 `001`, заявка не `done` или чужого Stay — 404 `002` |
| `POST /g/…/feedback/comment` | сессия | «Что было не так» после пальца вниз, один раз: `{request_id, comment}`; пустой или длиннее 500 знаков — 422 на границе; не к пальцу вниз или второй — 409 `004`; `passed_to_staff` — комментарий записан в карточку |
| `GET /g/static/feedback.js?v=` | нет | Виджет оценки с надписями и стилями (`feedback/widget.py`), общий для всех отелей, кэш навсегда — версию в адресе меняет содержимое. Роутер оценки подключён раньше чата: иначе путь съела бы страница `/g/{slug}/{room}` |

| `GET /g/static/photo.js?v=` | нет | Картинка в ленте и отправка с камеры с надписями и стилями (`photos/widget.py`), кэш навсегда. Грузит его загрузчик в скрипте страницы — только у страницы с камерой, по первой надобности; роутер фото подключён раньше чата, как у оценки |

| `GET /g/…/documents/data?language=` | сессия | Номер и даты проживания словами в поясе отеля, язык гостя (Р-9), `photos_read_by_ai` — фото читает модель (Р-13) |
| `POST /g/…/documents` | сессия | Multipart: `client_key`, `language`, `bill_to`, `note`, до 5 `files` → запрос АВР и карточка «Реквизиты получены» в чат; повтор ключа — тот же ответ; отказ файла — код узла и `details: [{file_position}]` |
| `GET /g/static/almaty-wallpaper.jpg?v=` | нет | Обои чата и листка (#773), общие для всех отелей: `wallpaper.py`, кэш навсегда — версию в адресе меняет содержимое файла. Объявлен в `router.py` раньше страницы чата: иначе путь съел бы `/g/{slug}/{room}` |
| `GET /g/static/chat-icon-{180,192,512}.png?v=` | нет | Иконка чата на экране «Домой» (spec 0068), пока общая для всех отелей; кэш и порядок маршрутов — как у обоев |
| `GET /w/{slug}/b/{token}` | нет | Страница ссылки привязки с листка (spec 0033 §6): consent-строка v3 + кнопка, шапка с отелем, как у чата; сессии не рождает |
| `POST /w/{slug}/b/{token}/session` | нет, rate-limit по IP | Нажатие кнопки-согласия: `start_guest_session_by_bind_link` (тот же путь, что код, P-12) → cookie + `chat_url`; ссылка многоразова до выезда (#354); браузер уже в чате этого Stay (cookie) — тот же диалог (#223); погашена или Stay погас — 403 `ERR-GUESTS-006`; токен длиннее 128 символов — 422; лимит — 429 `ERR-WEB-005` |

Короткий префикс `/w` — ради ёмкости QR; отдельный `bind_router` подключает
composition root рядом с основным. Маршруты меню и заказов — свой `menu/router.py`
под тем же `/g`: room service у отеля выключен (`TenantConfig.room_service`, spec 0038
Р-10) — любой из них отвечает 404 `ERR-ROOMSERVICE-002` раньше проверки сессии. Так же
устроены маршруты брони столика (`table/router.py`): бронь выключена или ресторанов нет —
404 `ERR-TABLEBOOKING-001`.

Контекст тенанта канал ставит САМ по slug внутри маршрутов (ADR-008 §6):
ни QR-slug, ни гостевая сессия НЕ входят в общий `TenantResolver` — гостевая
сессия на `/api/v1/*` конструктивно даёт 401 (тест-инвариант). Cookie:
HttpOnly + Secure + SameSite=Strict + Path=/g/{slug} и тот же токен на
Path=/w/{slug} — по нему привязка листком узнаёт браузер, который уже в чате
этого Stay (#223); атрибуты — не граница
безопасности, границу держит `guests.resolve_session` на каждом действии.
`{room}` из пути на аутентифицированных операциях игнорируется — комната
только из сессии (несовпадение логируется `web_path_room_mismatch`).

## Ключевые решения

- **Комната — из привязки, не из текста** (issue #79): `verified_room_number`
  Stay уезжает в ход (`ToolTurnContext`) — `create_service_request`
  перезаписывает комнату из аргументов модели; системный промпт получает блок
  «verified room» (модель не переспрашивает номер). Эскалации web-гостя несут
  комнату — персоналу есть куда прийти. Рядом едет `verified_stay_id` — сам Stay
  сессии: его пишут заявка инструмента и карточка эскалации (spec 0054).
- **Ключ чат-лимита — `stay_id`** (spec 0027 §3.2): повторный ввод кода рождает
  новую идентичность и не должен обнулять лимиты spec 0023.
- **Доставка исходящих — только запись** в `messages` (poll забирает);
  канал-осознанный подписчик — `channels/telegram/notifications.py`.
- **Итог заявки после закрытой страницы** (#223): push у веба нет, итог ждёт в
  диалоге. Три части: повторное сканирование листка с того же телефона —
  прежний диалог (cookie на `/w`, `GuestSessionBind.current_session_token`);
  после первой заявки диалога — статическая подсказка «итог придёт сюда, в этот
  чат» (`request_hint.py`, ключ на диалог, язык заявки; сбой подсказки ход не
  роняет; про закрытие страницы молчит — #857); при возврате — черта «Жаңа · Новое ·
  New» над сообщениями, пришедшими без гостя, и счётчик во вкладке, пока она
  скрыта (`assets/unread.js`, последнее увиденное — `localStorage`).
- **Вид — раскладка B+C на подложке «Небо и золото»** (#746: цвет — решение основателя
  03.11, раскладка — решение в #746 того же дня): шапка и строка ввода «под стекло» плавают
  над лентой и стоят на месте — прокручивается только `.scroller`, а страница не
  отскакивает (spec 0068 §2.3). Отступы прокрутки — высота шапки и строки ввода
  (`ResizeObserver`), поэтому в конце прокрутки последняя реплика стоит над строкой ввода
  любой высоты (плашки, пауза лимита, подсказка скрепки); колонка стоит на видимой
  области (`visualViewport`) — клавиатура iPhone строку ввода не закрывает. Шапка: пилюля языка слева, название и строка комнаты,
  знак отеля справа; тот же знак — у последнего ответа отеля подряд. Сообщения на
  сплошных пузырях (15 px), плашки дня («Сегодня», «27 октября» — словами браузера),
  время у сообщения, «печатает» на время хода, «Не доставлено» под самим сообщением
  (текст возвращается в поле, в том числе при обрыве сети); на 5xx и обрыве сети к нему —
  «Если срочно — позвоните на ресепшен» с цифрой `reception_room_dial`, которую страница
  взяла при загрузке (#991), то же на экране входа и ссылке с листка — на трёх языках. Пустой чат (в истории
  ничего) — крупное приветствие и плитки: две вставляют текст в поле, третья — меню
  room service, если он включён; плашка «Заказать в номер» над строкой ввода на это
  время уходит. Язык надписей после входа — выбор гостя в пилюле (`sessionStorage`),
  иначе язык телефона; до входа пилюля выключена. Пришёл по листку в пустой диалог —
  то же приветствие, что после ввода кода. Обои — картинка «Алматы» (#773) поверх
  градиента палитры: `mix-blend-mode: luminosity` берёт из неё только светлоту, ночью
  она инвертирована; грузится отдельным запросом после `load`, не загрузилась — остаётся
  градиент. Цвета и обои — пока общие для всех отелей; настройка из кабинета — #761.
- **Оценка выполненной заявки** (spec 0076 §5): под пузырём итога `done` — «Как всё
  прошло?» и два пальца, палец вниз открывает поле «что не так». Виджет — отдельный файл
  (`/g/static/feedback.js`): скрипт чата грузит его, когда в ленте впервые есть что
  оценить, — вес страницы (#746) не растёт, а гость без выполненных заявок и отель без
  оценок его не качают. «Передадим» и «передали» гостю — только при `passed_to_staff`
  (карточка в службе эскалаций есть), иначе «Спасибо за оценку!»; после перезагрузки
  страница говорит то же, что сразу после касания. Модель оценок не видит.
- **Чат как приложение** (spec 0068): манифест — свой у каждой комнаты, иконка открывает
  ту, с которой её добавили. У приложения с экрана «Домой» на iPhone свои cookie, а QR
  камерой открывает браузер, поэтому внутри приложения гость входит «комната + код»:
  поле комнаты заполнено из адреса и исправляется (переселили, чужая страница).
- **Экран входа = экран согласия** (spec 0029): кнопка ввода кода и есть
  согласие на обработку ПД. Тексты и версия — общий канон каналов
  (`channels/common/consent.py`, дословная копия `docs/legal/consent-text.md`),
  во всех трёх языках: до входа язык гостя неизвестен всегда. Ссылка — на
  страницу политики отеля `/legal/privacy/{slug}` (slug из адреса страницы;
  spec 0029 §11). Факт пишется на
  сессию (`guest_sessions.consent_*`) — своё согласие на каждую привязку;
  telegram хранит своё на диалоге, правило актуальности версии общее.
  Страница ссылки привязки — тот же канон: сессия рождается ТОЛЬКО по нажатию
  кнопки-согласия (открытие страницы — не согласие).

## Конфигурация

- `GUEST_CODE_VERIFY_RATE_LIMIT_ATTEMPTS` / `…_WINDOW_SECONDS` — лимит ввода
  кода по (tenant, room); `GUEST_CODE_VERIFY_IP_RATE_LIMIT_ATTEMPTS` — вторая
  ступень по IP за то же окно, проверяется первой (аудит 26.10 К-1, #483:
  поток выдуманных комнат с одного адреса гонял bcrypt на каждую); ≤0
  отключает ступень. Чат-лимиты — общие `GUEST_CHAT_RATE_LIMIT_*` (spec 0023).
- `GUEST_BIND_LINK_CONSUME_RATE_LIMIT_*` — лимит привязок по ссылке с листка
  по IP (spec 0033 §9); просторный — гости за NAT отеля делят один адрес. Сам
  адрес — канон `shared/clientip.py` (issue #207): за туннелем `request.client`
  указывает на соседний контейнер, и лимит был бы общим на всех гостей сразу.
  Бюджет тратит только отказ (ссылка не действует), как у входа персонала:
  до списания — `peek`, списание — по исходу (#415). Успешная привязка и
  повторный вход тем же листком бюджета не трогают: иначе группа в Wi-Fi
  отеля упиралась бы в 429 на исправных ссылках. Отказы лимитов входа видит
  алертер — ERR-OPS-014.
- `ENABLE_GUEST_REQUEST_PHOTOS` — фото к заявке (spec 0081 §4): камера и маршруты фото, только
  вместе с `ENABLE_SERVICE_REQUESTS`; умолчание `false`, копия отеля — `pilot-copy.md`.
- `TenantConfig.reception_phone` — телефон в статическом auth-only ответе.
- `TenantConfig.guest_chat_look` — вариант подложки, узор и знак отеля (spec 0066 §3);
  правит менеджер в кабинете («Вид гостевого чата»), конфига нет — вид #746.
- `PUBLIC_BASE_URL` — из него собирается ссылка на политику конфиденциальности
  в тексте согласия на экране входа (spec 0029 §2).

## Реквизиты для АВР (spec 0049, PR 4 серии #493)

Скрепка в строке ввода чата → форма: «На кого выставить», до 5 файлов (PDF, DOCX,
JPG, PNG, WebP), текст; номер и даты — из проживания сессии. Где работает (Р-7):
выключатель контура `ENABLE_GUEST_DOCUMENTS` **и** служба «Бухгалтерия»
(`accounting`) у отеля (`documents/hotel.py`) — иначе скрепки нет, маршруты 404.

- **Тело** читает только `platform/upload_form.read_upload_form` (CANONICAL):
  потолок 51 МБ до разбора, файлы в памяти, `/tmp` контейнера — tmpfs. Фото
  больше 5 МБ страница уменьшает в браузере до 2400 px (JPEG), HEIC в `accept` нет.
- **Отказы**, которые маршрут ждёт, — `AppError`, лог WARNING: ERROR-лог унёс бы
  поля формы в Sentry, пока открыт #433 (ревью PR #500, Н-1). У отказа узла по файлу
  страница называет файл своим текстом (`ERRORS` в `assets/documents.js`):
  ERR-FILES-001…003 и 007 — антивирус не пропустил ([spec 0075](../../../../docs/specs/0075-guest-file-antivirus.md)
  §5); прочие коды — общее «попробуйте ещё раз».
- **Подпись «Кто увидит»**: задан `LLM_MODEL_DOCUMENTS` — фото читает модель
  (Р-13), и подпись говорит, что фото прочитает ИИ (Anthropic, США) — политика
  §6 (#539). Настройку читает и `app`: compose передаёт её app и воркеру одной
  строкой `.env` (сверяет `test_documents.py`).
- **Сообщения гостю** (Р-2, `documents/messages.py`): «Реквизиты получены» пишет
  маршрут (ключ на запрос), «Готово» (ключ на проживание — дубль второго не даст)
  и «Вернули» с примечанием бухгалтера (ключ на заявку) — подписчик
  `request.status_changed`, регистрирует `worker.py`. Текст статический, на языке
  запроса, примечание — как написано; отмена гостем не пишет. Общий уведомитель
  гостя запрос не видит: у него нет `request_origins`. Возврат в работу (#998) —
  «Ещё не готовы» (ключ на заявку и номер возврата), если «Готово» этого закрытия
  ушло и у проживания нет другого выполненного запроса; «Готово» после возврата — только
  после поправки или если проживанию его ещё не писали (spec 0080 §2.3).
- Логи: `act_request_form_opened`, `act_request_file_rejected` (код и номер файла),
  `act_request_message_recorded` / `…_skipped_duplicate` / `…_skipped_reopened` /
  `…_skipped_not_ready`,
  `act_request_received_message_failed` (WARNING: запрос принят, карточки нет).

## «Заказать в номер» (spec 0038, PR 5)

Гость жмёт «Заказать в номер» в чате: вкладки «Ресторан» и «Магазин» (какие
открыты у отеля), разделы и карточки, корзина своя у каждого каталога, лист товара
снизу. «Далее» берёт итог у сервера (`…/menu/quote`), «Оформить заказ» шлёт его как
`expected_total_minor` и ключ кнопки (`client_order_key`): двойное нажатие и повтор
после сбоя — один заказ. Экран заказа опрашивает `…/orders/{id}` раз в 8 с, пока
заказ открыт; отменить можно, пока он не оплачен («Отправлен», «Идём за оплатой»):
заказ принят только после оплаты. Вид — по прототипу-эталону spec
0038, светлая и тёмная темы; шрифты системные (без Google Fonts — IP гостя никуда
не уходит). Всё, что пришло с сервера, скрипт выводит через `esc()`: названия
вносит персонал. Язык — kk/ru/en из языков отеля, переключатель в шапке, выбор
помнит `sessionStorage`. Корзины — тоже в `sessionStorage` вкладки.

Нештатное (#755): меню → корзина → оформление → заказ — записи истории браузера
(`nav.js`), системная «Назад» телефона ведёт на прошлый экран, а не в чат. Меню не
загрузилось — экран «Не удалось загрузить меню» с «Попробовать снова» и одним
автоповтором через 3 с. Ошибки — плашкой внизу над кнопкой, 6 с; без связи — свой
текст `err_offline`. «Очистить» корзину — с «Вернуть» 5 с. Лист закрывается «×» и
свайпом вниз. Документы так же: не загрузились — «Попробовать снова», ошибка поля — под
полем, сбой отправки — плашкой внизу.

Сообщения в чат (`menu/messages.py`) — на языке заказа, статическими текстами без
модели: «Оформлен» (`request.created`), «Иду за оплатой» (`new → in_progress`),
«Оплачено» — заказ принят (`request.payment_marked`), «Доставлено» (`done`; примечания персонала
гостю нет — ревью PR #520, Н-9), «Отменён» сотрудником с причиной (нет причины — «Другое»).
Отмена гостем в чат не пишется. Ключ — на шаг, повторное «Иду за оплатой» после возврата в
очередь второго сообщения не даёт. «Доставлено» не тому заказу вернули в работу (#998) —
«Простите, мы поторопились: заказ #N ещё не доставлен», следующее «Доставлено» — с номером
возврата в ключе (`form_reopen.py`). Адрес — веб-диалог по `guest_identity_id`
заказа; страница чата заберёт сообщение опросом. Подписчика подключает воркер.

## «Забронировать столик» (spec 0064, PR 2 серии #702)

Гость жмёт «Забронировать столик» в чате: сверху «Ваши брони» этого проживания, ниже
форма — ресторан, день («Сегодня», «Завтра», дальше датами), слот времени, гости
(больше `max_party` — подсказка «ресторан бронирует сам»), «На чьё имя» и «Пожелания».
Под кнопкой «Отправить запрос» — «Это запрос, а не бронь». Ключ кнопки (`client_key`):
двойное нажатие — один запрос; «Запросить на 20:30» после «Другого времени» шлёт новый
запрос с ключом от брони — повтор нажатия тот же. Стадии опрашиваются раз в 8 с, пока
есть запрос без ответа; опрос перерисовывает только список, не форму, где гость печатает.
Час брони прошёл без ответа — «Ресторан не ответил вовремя…» (вычисляется при показе).
Вид — стили «Заказать в номер», тёмная тема оттуда же; язык — kk/ru/en, переключатель в
шапке, выбор помнит `sessionStorage`; дата и время — по часам отеля с сервера.

Сообщения в чат (`table/messages.py`) — на языке брони, статическими текстами без модели:
«Запрос отправлен» (`request.created`), ответ ресторана (`done` — «Подтвердить», «Другое
время», «Мест нет»; без ответа — «не ответил»), «не ответил» и при отмене заявки не гостем.
Отмена гостем в чат не пишется; заявка «Гость отменил бронь» — не бронь, подписчик молчит.
Ключ — на шаг. Ответ не на ту бронь вернули в работу (#998) — «ответ … отправлен по ошибке»,
ответ снимает `table_booking`, следующее закрытие — с номером возврата в ключе. Подписчика
подключает воркер.

## Типовые сценарии изменения

- **Публичные вопросы неавторизованным** (Phase 2, Q7) — per-channel конфиг
  тенанта; auth-only здесь остаётся дефолтом.

- **Auth-only в Telegram** — тот же `guests.start_guest_session` с
  `identity_kind=telegram`; этот канал не меняется.
