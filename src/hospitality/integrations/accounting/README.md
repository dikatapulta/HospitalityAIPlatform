# integrations/accounting — адаптеры учётной системы отеля

Реализации порта `AccountingPort` (`shared/ports/accounting.py`,
[spec 0052](../../../../docs/specs/0052-act-requisites-1c-export.md), FOUNDATION §8).
Подключает только composition root — `app.py` зовёт `build_accounting()` и кладёт
результат в порт (`set_accounting`). Ядро и модули адаптеры не импортируют (контракт 2
import-linter); модуль `documents` зовёт порт через `get_accounting()`.

## Что умеет

Отдаёт контрагентов файлом, который бухгалтер загрузит в свою учётную систему: строка
заголовка и по строке на контрагента — реквизиты, номер и даты проживания. С 1С адаптер
не соединяется: это упрощённый адаптер §8 правила 5.

Собирает файл черновика АВР по форме Р-1 из снимка, который подтвердил бухгалтер
([spec 0086](../../../../docs/specs/0086-work-completion-act-draft.md)): `render_act(act,
file_format=…)`. Excel — лист формы на A4 альбомом: стороны с ИИН/БИН, договор, номер и
дата, таблица из восьми граф, «Итого», «Сдал»/«Принял» и сноски; количество, цена и
стоимость — числами, прочее — текстом. Адаптер ничего не считает. PDF — PR 3 серии.

| Адаптер | Файл | Что отдаёт | Для чего |
|---|---|---|---|
| `OneCXlsxAccountingAdapter` | `onec_xlsx.py` + `xlsx.py`; акт — `act_xlsx.py` | Excel (.xlsx) для загрузки в 1С из табличного документа; черновик АВР формы Р-1 | кабинет: «Скачать для 1С», файл акта |
| `FakeAccountingAdapter` | `fake.py` | JSON той же таблицы; справочник «1С» в памяти по БИН/ИИН (`counterparties`), выданные файлы (`exports`); акт — JSON снимка, собранные акты (`acts`) | тесты, CI (ADR-007) |

Excel собирается без сторонних библиотек (`zipfile` + XML): общая таблица строк, текст —
с форматом «@», заголовок жирным; у акта ещё числа (`Decimal`, сумма — `#,##0.00`),
рамки, объединённые ячейки и печать альбомом по ширине (`build_sheet`). Значение «=…» из реквизитов гостя —
строка, а не формула; символы, которых не допускает XML, выбрасываются.

## Конфигурация

Нет: адаптер один и внешней системы не трогает, Excel работает и локально, и на контуре.
Второй адаптер (XML обмена 1С или настоящая интеграция) выбирается конфигурацией тенанта
(FOUNDATION §8 правило 3).

## Лимиты

Строк — сколько передал модуль (`documents` ставит потолок 1000, `EXPORT_LIMIT`); поле —
до 300 знаков (spec 0049 §4). Файл собирается в памяти и не хранится.

## Health и метрики

- `check()` — всегда `True`: внешней системы нет. В `/health/ready` не входит.
- Метрика `act_requisites_exports_total{tenant_id,outcome}` и лог `act_requisites_exported`
  пишет модуль `documents` вокруг вызова порта — одни на все адаптеры.

## Тесты

Один контрактный набор на оба адаптера — `tests/test_accounting_port.py` (R-7): Excel
разбирается как настоящий .xlsx (zip + XML), Fake — как JSON. Акт — `tests/test_accounting_port_acts.py`: номер,
стороны, строки и суммы в файле, имя, воспроизводимые байты; у Excel — графы формы Р-1 по
адресам ячеек, формул нет.
