# concierge — знания о городе для консьержа гостя

## Назначение

Справочник города — общие знания (FOUNDATION §7.4): что посмотреть, как добраться, сезоны и
практичные мелочи. Записи не принадлежат отелю: их пишет и проверяет платформа, у каждой —
источник и дата проверки ([spec 0085](../../../../docs/specs/0085-city-guide-almaty.md), #952).
Отель справочник не правит, а подключает флагом `TenantConfig.city_guide_enabled`; какой
город — решает профиль отеля (`profile.city`, `profile.country_code`). Сейчас город один —
Алматы, черновик.

Модуль только хранит и отдаёт данные. Текст для модели собирает AI-слой
(`ai/city_guide.py`), блоком системного промпта по канону справочника отеля (spec 0036 §4).

## Состав

| Файл | Что даёт |
| --- | --- |
| `api.py` | Публичный интерфейс: единственная точка импорта извне (R-5) |
| `city_guide.py` | Схемы `CityGuide` и `CityGuideEntry`, пределы, загрузка файлов `data/`, выбор по профилю, ссылка карты |
| `data/almaty.toml` | Справочник Алматы: шапка (имя, страна, написания города) и записи `[[entries]]` |
| `tests/` | Каждый файл проходит схему; выбор по написанию города и стране; источник и дата у каждой записи; ни цен, ни экстренных номеров; отказы схемы; ссылка карты |

## Публичный API

- `city_guide_for(city, country_code) -> CityGuide | None` — справочник города отеля.
  Сравнение без регистра, лишних пробелов и разницы «-»/пробел; страна обязана совпасть.
  Нет справочника — `None`.
- `all_city_guides() -> tuple[CityGuide, ...]` — все справочники, проверенные схемой; файлы
  читаются один раз на процесс.
- `CityGuide` — `key` (имя файла), `name` (имя в заголовке блока и в запросе карты),
  `country_code`, `aliases`, `entries`; `map_url(entry)` — ссылка поиска места в Google Maps
  (без ключа), у записи без `map` — `None`. Ссылку строит код, модель её только переписывает.
- `CityGuideEntry` — `topic` (≤ 40 знаков, без «/»), `text` (≤ 300, одна строка),
  `local_name` (имя для таксиста), `map` (запрос поиска латиницей), `source` (https),
  `checked` (дата проверки).
- Пределы: `MAX_CITY_GUIDE_ENTRIES` = 60, `MAX_CITY_GUIDE_TOPIC_LENGTH` = 40,
  `MAX_CITY_GUIDE_TEXT_LENGTH` = 300, `MAX_CITY_GUIDE_TOTAL_TEXT_CHARS` = 12 000 —
  обоснование чисел в spec 0085 §3–§4.

## События

Не публикует и не потребляет.

## Таблицы

Нет: справочник — файл данных в репозитории, а не данные тенанта.

## Зависимости

`shared.logging`, pydantic, stdlib `tomllib`. Модулей и интеграций не импортирует.

## Типовые сценарии изменения

- **Поправить или добавить запись** — правка `data/<город>.toml`: источник — ссылка, по которой
  факт проверен сегодня, `checked` — сегодняшняя дата. Правила содержимого (без цен, расписаний,
  экстренных номеров и заведений по имени) — spec 0085 §6; часть из них ловит тест модуля.
- **Новый город** — новый файл `data/<ключ>.toml` той же формы; отель подключает его флагом,
  город берётся из профиля. Тест «каждый файл проходит схему» перечисляет ключи — дописать.
- **Вырос справочник** — предел суммы знаков стоит денег каждого хода (spec 0085 §4): поднимать
  вместе с пересчётом цены в спеке.
