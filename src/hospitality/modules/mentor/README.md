# mentor — «Наставник» персонала: кодекс отеля, диалоги, оценки, экзамен и идеи

## Назначение

Сотрудник спрашивает о стандартах отеля и получает ответ по статьям кодекса со ссылкой, а в
«Тренировке» отвечает на вопросы по статьям, а «Экзамен» сдаёт серией вопросов с итогом в
процентах ([spec 0048](../../../../docs/specs/0048-mentor.md), issue #492; экзамен — §12, #779). Экзамен
назначает менеджер — всем или службам, и итог считается только по назначенному ([spec
0072](../../../../docs/specs/0072-mentor-exam-rollout.md) §3, #898). Пока кодекс — проект
(«Статус: проект» в шапке), экзамен сдаётся только пробно — в итог по назначению не идёт; сотрудник отмечает «Неточность
в статье», а «Где ошибаются» показывает число отметивших (там же, §6). Отдельный модуль, а не база знаний гостя — [ADR-023](../../../../docs/adr/ADR-023-mentor-module.md):
стандарты персонала не должны попасть в ответ гостю (§7.6).

Третий и четвёртый режимы диалога — «Предложить идею» и интервью служб ([spec
0071](../../../../docs/specs/0071-staff-ideas.md), #871): сотрудник рассказывает идею, ИИ уточняет
и предлагает пересказ — карточку; отправленная карточка закрывает разговор, следующая идея
начинает новый. Флаг раздела — `TenantConfig.ideas_enabled`, независимо от `mentor_enabled`.

Модуль о модели не знает: поиск принимает готовый вектор, запись диалога — готовый текст.
Эмбеддинги, промпты и поток ответа — композиционный слой `ai/mentor/` (ADR-023), права и экраны
— кабинет (`staff_portal/mentor.py`, `mentor_api.py`), флаг раздела — `TenantConfig.mentor_enabled`
(проверяет кабинет).

## Публичный API

- `parse_codex_files(files) -> list[CodexArticleDraft]` — статьи по порядку; ошибка разметки —
  `ERR-MENTOR-001` (422, «Файл 20_front_office.md, строка 41: статья 15 вместо 14»). Файлы
  читаются по имени.
- `replace_codex(files, *, embeddings, embedding_model, uploaded_by_user_id) -> CodexInfo` —
  кодекс и статьи целиком одной транзакцией; ошибка разметки — до записи, старый кодекс
  остаётся. `embeddings=None` — без векторов (сид). Две загрузки разом упорядочивает upsert строки
  кодекса.
- `get_codex()`, `has_codex()`, `load_codex_document()` — сведения, «загружен ли», дерево для
  страницы «Кодекс». `codex_is_draft()` — загружен и он проект (spec 0072 §6), по шапке без
  разбора файлов. Загрузка (`replace_codex`) той же транзакцией снимает отметки «Неточность в
  статье» статей, у которых сменились название, текст или источник, и пропавших.
- `search_articles(vector, *, limit)` — ближайшие по `<=>` без индекса; статьи без вектора не
  участвуют. `get_articles(numbers)` — по номерам, несуществующие отброшены.
- `list_articles_needing_embedding(model)` / `store_article_embeddings(vectors, *, model)` —
  статьи без вектора или с вектором другой модели и запись векторов.
- `pick_quiz_article(*, chapter_number, near, exclude)` — статья от `QUIZ_MIN_ARTICLE_CHARS`
  (250) знаков; длинных нет — любая. С вектором темы — ближайшая из трёх не спрошенных недавно,
  без темы — случайная.
- `get_conversation(user_id, mode)`, `append_messages(...)`, `compact_history(user_id,
  conversation_id, ...)` — открытый диалог сотрудника (один на `(user_id, mode)`; закрывает
  его только отправленная идея), реплики по порядку,
  резюме старой части. Резюме пишется только в диалог `conversation_id`, прочитанный ходом:
  стёрт «Начать заново», пока писалось резюме, — резюме не пишется ни в него, ни в новый
  диалог, который успел завести следующий вопрос (#531, #492).
- `start_quiz_question(...)`, `active_quiz_question(user_id)` — вопрос «Тренировки» (статья
  уходит в последние `QUIZ_NO_REPEAT` = 6). `record_quiz_answer(...)` — до показа проверки
  (#966): снимает вопрос, пишет ответ сотрудника и строку оценки, отдаёт id диалога;
  `add_quiz_verdict(user_id, conversation_id, verdict)` — проверка после конца потока, только
  в тот же диалог (стёрт «Начать заново» — `False`, новый не заводится). Вопроса нет, он
  сменился или уже засчитан — `ERR-MENTOR-003` (409).
- `delete_conversation(user_id, mode)` — «Начать заново»: открытый диалог режима с черновиком
  идеи; отправленные идеи и их разговоры остаются.
- `quiz_stats_by_chapter(user_ids=…)`, `quiz_stats_by_user(user_ids=…)`, `quiz_stats_since(user_ids=…)`
  — «Где ошибаются»: верно / частично / неверно по главе (снимок номера и названия) или по
  сотруднику; считаются только учётки из `user_ids` — кабинет передаёт «Сотрудников» отеля, без
  стёртых суперадмином. `reset_quiz_stats()` — «Обнулить» (все оценки отеля, число строк).
- `start_exam(user_id, *, chapter_number, question_count, pass_percent)` — экзамен для себя:
  новая попытка со снимком числа вопросов, порога и «кодекс — проект» (`on_draft_codex`); идущая прежняя остаётся брошенной (без
  итога, в итоги не идёт). Кодекса нет — `ERR-MENTOR-002`; главы нет в кодексе — весь кодекс.
  `current_exam(user_id)` — идущая попытка (последняя начатая без итога) или `None`.
- `pick_exam_article(*, chapters, exclude)` — статья вопроса из глав `chapters` (`None` — весь
  кодекс): не спрошенная в попытке, сначала от 250 знаков, затем короткая, спрошены все — повтор.
- `set_exam_question(user_id, attempt_id, *, turn, article_number, question)`,
  `record_exam_answer(..., grade)`, `drop_exam_question(...)` — ход под блокировкой строки:
  попытка, номер хода `turn` и открытый вопрос сверяются, иначе `ERR-MENTOR-004` (409). Оценка
  `None` — ответ не засчитан (`ungraded_count`); последний засчитанный — итог: `exam_percent`
  (верно — 1, частично — 0,5; вниз до целого) и «сдан» при проценте не меньше порога.
- `list_exam_attempts(user_id, *, limit=EXAM_ATTEMPTS_SHOWN)` — законченные попытки, свежие сверху.
- `create_exam_assignment(*, chapter_numbers, service_keys, created_by_user_id)` — назначенный
  экзамен (spec 0072 §3): `chapter_numbers=None` — весь кодекс, иначе снимок «номер + название»
  найденных в кодексе глав (не нашлось ни одной — `ERR-MENTOR-006`); `service_keys` пусто — всем
  (ключи сверяет кабинет). `archive_exam_assignment(id)` — «Снять» (`False` — нет или уже снято);
  `list_exam_assignments()` — действующие, свежие сверху; `get_exam_assignments(ids)` — и снятые.
- `start_assigned_exam(user_id, assignment_id, *, service_keys, question_count, pass_percent)` —
  попытка назначения: снято, не для служб сотрудника или ни одной главы нет в нынешнем кодексе
  (по номеру и названию) — `ERR-MENTOR-006` (409). `exam_attempt_chapters(attempt)` — главы
  следующего вопроса (`None` — весь кодекс); начатая попытка снятого назначения доходит до итога.
- `assigned_exam_results(*, assignment_ids, user_ids)` — итог по назначению, ключ `(назначение,
  сотрудник)`: первая сданная попытка, иначе последняя законченная; пробная (на проекте кодекса,
  spec 0072 §6) — только пока зачётных нет, и `ExamAttemptRead.passes_assignment` у неё ложно («Итоги экзаменов», #780);
  учётки передаёт кабинет — стёртых модуль не знает. `ungraded_exam_answers(*, assignment_ids,
  user_ids)` — не засчитанные ответы по назначению (оценку модели не разобрать), сумма по всем
  попыткам, законченным и нет (#1050).
- `mentor_activity(*, created_after, created_before) -> MentorActivity` — «пульс пользы» копии
  сводки основателю (spec 0035 §8.1): реплики сотрудников во всех режимах и сколько разных
  сотрудников, попытки экзаменов начато / закончено / сдано (личные и назначенные, пробные
  тоже), не засчитанные ответы попыток, начатых в окне. `has_active_exam_assignment()` — есть ли
  не снятое назначение (условие сигнала «тихий день», ERR-OPS-022).
- `set_article_flag(user_id, article_number, *, flagged)` — «Неточность в статье» (spec 0072 §6):
  отметить или снять свою; ответ — стоит ли отметка; статьи нет в кодексе — не пишется (`False`).
  `my_article_flags(user_id)` — номера своих отмеченных статей; `article_flag_counts(user_ids=…)`
  — статьи с числом отметивших (только учётки из `user_ids`), больше — выше, затем по кодексу.
- `save_idea_draft(user_id, conversation_id, *, summary, mark, mark_note)` — черновик карточки
  из предложения модели (spec 0071 §3), заменяет прежний; диалог уже не открыт — `None`, не
  пишется (как резюме, #531). Режим `ask`/`quiz` или пометка к итогу интервью — `ValueError`.
  `get_idea_draft(user_id, mode)` — черновик открытого диалога режима.
- `send_idea(user_id, idea_id, *, summary)` — «Отправить разработчику»: пересказ из поля
  автора, `sent_at`, диалог закрыт. Черновика нет, он чужой или уже отправлен —
  `ERR-MENTOR-005` (409).
- `list_my_ideas(user_id)` — отправленные карточки автора, свежие сверху;
  `delete_my_idea(user_id, idea_id)` — карточка вместе с разговором, только своя.
- `list_sent_ideas(*, unreviewed_only=False)` — «Все идеи» (spec 0071 §8): отправленные карточки
  всех авторов отеля с репликами разговора (`SentIdeaRead`), свежие сверху; черновиков нет. Права
  (только суперадмин) режет кабинет. `mark_idea_reviewed(idea_id)` — «Разобрано»: повтор первую
  отметку не меняет; черновика или карточки другого отеля нет — `False`.
- `count_sent_ideas(*, sent_after, sent_before)` — число отправленных идей отеля (`kind = idea`)
  за окно, без авторов и служб — лист «Отчёт» менеджера (spec 0083 §2.3).
- `delete_expired_mentor_texts(*, created_before)` — реплики, резюме и черновики идей старше
  границы, отправленные идеи — старше `IDEA_RETENTION_DAYS` (365) от `sent_at` вместе с
  разговором (зовёт `channels/common/retention.py`, срок реплик — как у текстов гостя,
  spec 0032). Идемпотентна.

## Таблицы

Миграция 0043 (RLS-канон 0002, `CREATE EXTENSION vector`): `mentor_codexes` (файлы `{name, text}`
массивом, одна строка на тенанта), `mentor_codex_articles` (статья + `vector(1536)` и модель
вектора), `mentor_conversations` (резюме и момент резюме, текущий вопрос, последние статьи
вопросов), `mentor_messages` (реплика, ссылки на статьи, `in_summary`), `mentor_quiz_answers`
(оценка без текста ответа). Миграция 0058: `mentor_exam_attempts` (попытка экзамена: снимок
настроек, счёт, открытый вопрос, итог; текстов ответов нет). Миграция 0063:
`mentor_conversations.closed_at` и частичная уникальность открытого диалога режима;
`mentor_ideas` (карточка идеи или итог интервью, одна на диалог; у интервью пометки нет —
CHECK). Миграция 0067: `mentor_exam_assignments` (назначенный экзамен: снимок глав и ключи
служб массивами, автор, когда снят) и `mentor_exam_attempts.assignment_id` (FK `ON DELETE SET
NULL`, пусто — экзамен для себя). Миграция 0069: `mentor_exam_attempts.on_draft_codex` (попытка
начата на проекте кодекса — пробная) и `mentor_article_flags` (отметка «Неточность в статье»: сотрудник и
номер статьи, одна на пару). Строки ПД — `docs/PII_REGISTRY.md`.

## Зависимости

## Типовые сценарии изменения

- Смена модели эмбеддингов с другой размерностью → миграция колонки и
  `ARTICLE_EMBEDDING_DIMENSIONS` (тест сверяет его со шлюзом); векторы досчитаются сами.
- Новый срез «Где ошибаются» → чтение `mentor_quiz_answers` в `stats.py`; права на срез — кабинет.
- Сводка экзаменов (по службам — #780) → итог по назначению в `assignments.py`
  (`assigned_exam_results`), только учёток из списка кабинета (как `stats.py`).
- Правило разметки → `codex.py` и образцы в `tests/test_codex_parser.py`; старые загруженные
  кодексы перечитываются этим же разбором.
