{# Каркас страницы кабинета (spec 0033 §4, ADR-014; CANONICAL). Страницы наследуют его: block title/brand/content. shell — каркас страниц отеля (v3 — issue #635 по макету основателя; кладёт только router._hotel_page, контекст — shell.shell_context). Компьютер: боковое меню группами «Работа» / «Управление» со счётчиком открытых заявок, отель сверху (ссылка на выбор — только при нескольких членствах), профиль снизу — в его меню тема «Системная / Тёмная / Светлая» и «Выйти». Телефон (≤ 960 px): шапка с отелем, нижняя панель на 4 раздела + «Ещё» (остальные разделы, тема, выход) и круглая «+» — новая заявка. Тема и меню — shell.js, он подключён в без defer: тема ставится до первой отрисовки. Без shell — простая шапка: block brand, display_name включает блок «кто вошёл + Выйти»; show_logout — кнопка «Выйти» без имени (403-страница: сессия жива, членства нет). Страницы до входа (`_auth.html`, #637) простую шапку снимают пустым block topbar. Логаут — POST, не ссылка: GET не меняет данных — часть CSRF-контракта router.py; форм выхода в каркасе две (меню профиля и «Ещё»), push.js перехватывает каждую. signal — адреса сигнала кабинета (spec 0039 §3, router._hotel_page): есть на каждой странице отеля и подключает static/signal.js; плашки сигнала — здесь, JS только показывает и прячет их (разметки в JS нет, README); значок плашки — линейная иконка _icons.html, не эмодзи (#757): эмодзи рисуется по-своему на каждой системе и в тёмной теме пятном; строки замечаний ресепшену JS клонирует из
